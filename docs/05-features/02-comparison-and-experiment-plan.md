# 제품 비교와 실험 계획

## 한눈에 보기

후보 제품 하나를 현재 안정 루틴에 추가하거나 제품 하나와 교체한 가상 루틴을 만든다. 서비스는 달라지는 요소를 계산하고, 여러 후보 중 먼저 시험할 제품을 제안한다. 사용자가 후보를 고르면 한 제품만 포함한 실험 계획과 관찰 퀘스트를 만든다.

연결 요구사항: `FR-CMP-001~003`, `FR-EXP-001~005`, `FR-REC-005~006`

## 1. 비교할 수 있는 후보

연결 이슈: [#13 새 제품의 추가·중복·교체 요소 비교](https://github.com/sksksksksksss/service/issues/13)

비교를 시작하려면 다음 정보가 있어야 한다.

- 후보가 참조하는 안정 루틴 버전
- 후보 제품과 데이터 확인 상태
- 사용 목적
- `추가` 또는 `교체` 의도
- 교체라면 제거할 제품과 적용 시간대

안정 루틴이 후보 저장 후 바뀌었으면 과거 결과를 새 결과처럼 보여주지 않는다. 최신 안정 루틴으로 다시 비교하거나 후보를 보관·삭제하도록 한다.

## 2. 루틴 차이 계산

### 가상 루틴 생성

- `추가`: 선택한 시간대와 순서에 후보 제품 하나를 넣는다.
- `교체`: 지정한 안정 루틴 제품을 제거하고 같은 위치에 후보를 넣는다. 사용자가 순서를 바꿀 수 있다.
- 안정 루틴 원본은 수정하지 않는다.

### 계산 결과

| 결과 | 의미 |
| --- | --- |
| 추가 제품 | 안정 루틴에 없고 가상 루틴에 있는 제품 |
| 제거 제품 | 교체 의도로 가상 루틴에서 빠진 제품 |
| 유지 제품 | 안정 루틴과 같은 시간대·방식으로 남은 제품 |
| 새 기능 | 확인된 기능 중 안정 루틴에 없던 기능 |
| 중복 기능 | 안정 루틴 제품과 후보가 함께 제공하는 기능 |
| 사라지는 기능 | 교체 대상 제거로 루틴에서 더 이상 확인되지 않는 기능 |
| 관찰 항목 | 사용자 목적, 주요 변화와 개인 이력을 기준으로 확인할 변화 |

성분은 전체 차집합을 기본 화면에 나열하지 않는다. 다음 조건 중 하나에 해당하는 성분·기능만 주요 변화로 보여준다.

- 사용자의 우선 목적과 직접 연결된다.
- 안정 루틴에서 반복되는 기능을 더한다.
- 과거 개인 실험의 문제없음·불편 결과와 연결된다.
- 제품 데이터 정책에서 별도 관찰 대상으로 표시되어 있다.
- 교체로 사라지는 주요 기능을 설명하는 데 필요하다.

`별도 관찰 대상`은 의학적 위험 판정이 아니라 운영자가 근거와 출처를 등록한 설명 태그다.

### 정보 부족

- 후보의 기능이 확인되지 않으면 기능이 없다고 판단하지 않고 `정보 부족`으로 표시한다.
- 개인 초안 성분이 미확정이면 해당 성분을 비교 근거에서 제외한다.
- 서로 다른 이름의 동일 성분은 정규화 식별자가 확인된 경우에만 같은 것으로 취급한다.

### 완료 조건

- **Given** 추가 후보, **When** 비교하면, **Then** 안정 루틴은 그대로이고 추가·유지 제품과 기능 중복이 계산된다.
- **Given** 교체 후보, **When** 비교하면, **Then** 제거 제품과 함께 사라질 수 있는 기능이 표시된다.
- **Given** 확인되지 않은 성분 정보, **When** 비교하면, **Then** 없음으로 단정하지 않고 정보 부족으로 표시한다.

## 3. 먼저 시험할 후보 제안

연결 이슈: [#14 먼저 시험할 제품과 추천 이유 확인](https://github.com/sksksksksksss/service/issues/14)

후보 순서는 다음 우선순위로 계산한다.

1. 사용 목적과 확인된 기능이 일치하는가
2. 동일 제품의 개인 결과가 있는가
3. 반복된 개인 관찰 패턴과 일치하거나 충돌하는가
4. 안정 루틴에서 새로 생기는 변수가 적고 비교가 분명한가
5. 기능·성분 정보의 확인 수준이 충분한가

불편했던 제품 또는 관련 개인 패턴을 자동으로 영구 제외하지 않는다. 사용자가 다시 시험할 수 있지만 먼저 시험할 후보에서 낮추고 반대 근거를 명시한다.

후보가 하나면 순위 경쟁을 만들지 않고 바로 비교 결과와 실험 시작 행동을 보여준다. 후보가 여러 개면 첫 후보와 나머지 후보의 차이를 문장으로 설명한다.

### 설명 구성

- `먼저 시험하는 이유`
- `현재 루틴에서 달라지는 점`
- `이 후보보다 뒤로 둔 이유`
- `개인 경험 반영`
- `아직 모르는 점`

AI는 계산 결과를 설명할 뿐 순서를 재결정하지 않는다.

### 완료 조건

- **Given** 두 개 이상의 후보, **When** 순서를 계산하면, **Then** 모든 후보에 순서와 비교 가능한 근거가 남는다.
- **Given** 과거 불편 결과와 연결된 후보, **When** 재시험 후보가 되면, **Then** 이전 결과와 낮아진 판단 근거가 표시된다.

## 4. 근거와 불확실성

연결 이슈: [#16 추천의 반대 근거·불확실성·부족한 정보 확인](https://github.com/sksksksksksss/service/issues/16)

모든 추천·순서 설명은 다음 구조를 사용한다.

| 구분 | 예시 |
| --- | --- |
| 지지 근거 | 사용 목적과 확인된 보습 기능이 일치한다. |
| 반대 근거 | 현재 루틴의 크림과 보습 기능이 겹친다. |
| 개인 근거 | 이전 동일 제품 실험에서 문제없이 사용했다. |
| 정보 부족 | 후보의 일부 성분은 사용자 확인 전이다. |
| 다른 변수 | 당시 수면 부족을 함께 기록해 과거 불편 결과의 확신이 낮다. |

근거 강도는 `충분`, `제한적`, `부족` 세 단계로 표시한다.

- `충분`: 안정 루틴, 변경 의도, 확인된 제품 데이터가 있고 동시 변경이 없다.
- `제한적`: 핵심 비교는 가능하지만 일부 성분·개인 기록이 부족하다.
- `부족`: 안정 루틴 또는 변경 의도가 없거나 제품 핵심 정보가 미확정이다.

근거 강도는 제품이 잘 맞을 확률이 아니다. 입력과 비교를 얼마나 재현할 수 있는지만 나타낸다.

## 5. 실험 계획 만들기

연결 이슈: [#15 한 제품씩 시험하는 사용·관찰 계획 생성](https://github.com/sksksksksksss/service/issues/15)

### 기본 계획

- 실험 제품: 후보 하나
- 기준 안정 루틴 버전
- 추가·교체와 적용할 시간대·순서
- 시작 예정일
- 종료 예정일: 기본 14일, 사용자가 7~28일 범위에서 변경
- 관찰 항목
- 동시에 바꾸지 않을 항목

### 자동 생성 퀘스트

| 퀘스트 | 예정 시점 | 필수 여부 |
| --- | --- | --- |
| 첫 사용 | 사용자가 실제 첫 사용을 시작한 시점 | 필수 |
| 초기 확인 | 첫 사용 시각 + 24시간 | 필수 |
| 중간 확인 | 실제 시작과 종료 사이의 중간 날짜 | 필수 |
| 최종 결과 | 종료 예정일 | 필수 |

예정 시점은 운영 기본값이며 안전성·효능 기준이라고 설명하지 않는다. 사용자가 기간을 바꾸면 아직 완료하지 않은 중간·최종 퀘스트만 다시 계산한다.

### 한 번에 한 실험

- 후보 목록은 여러 개 유지할 수 있다.
- `PLANNED`, `ACTIVE`, `PAUSED` 실험은 합쳐서 하나만 존재할 수 있다.
- 새 실험을 시작하려면 기존 실험을 완료 또는 취소한다.
- 다른 제품도 실제로 바꿨다고 사용자가 기록하면 Rescue의 동시 변경 정보에 포함하고 비교 확신을 낮춘다.

### 상태 전환

| 현재 | 행동 | 다음 상태 | 추가 처리 |
| --- | --- | --- | --- |
| 없음 | 계획 확정 | PLANNED | 필수 퀘스트 초안 생성 |
| PLANNED | 첫 사용 기록 | ACTIVE | 실제 시작 시각 확정, 퀘스트 예정일 계산 |
| PLANNED | 취소 | CANCELLED | 취소 이유 선택 |
| ACTIVE | 일시 보류 | PAUSED | 향후 예정 퀘스트 중지 |
| PAUSED | 일반 사유로 재개 | ACTIVE | 중지 기간만큼 미완료 퀘스트 이동 |
| ACTIVE·PAUSED | 최종 결과 기록 | COMPLETED | Archive 반영, 완료 연구 기록 생성 |
| ACTIVE·PAUSED | 취소 | CANCELLED | Archive에는 취소 이력으로 보존 |

불편함 때문에 보류한 실험은 같은 실험으로 재개하지 않는다. 먼저 `보류` 또는 다른 최종 결과로 완료하고, 사용자가 다시 안정되었다고 확인한 뒤 연결된 새 재시험을 만든다. 여행·제품 분실처럼 피부 불편과 무관한 사유만 같은 실험으로 재개할 수 있다.

### 계획 변경

- 첫 사용 전에는 제품을 제외한 계획 값을 수정할 수 있다.
- 첫 사용 후 제품과 기준 안정 루틴은 바꿀 수 없다.
- 사용 시간대·순서를 실제로 바꾼 경우 변경 시점 이력으로 남긴다.
- 종료일을 과거로 바꿀 수 없으며 7~28일 범위를 지킨다.

### 완료 조건

- **Given** 진행 중인 실험이 없는 사용자, **When** 후보 하나로 계획을 확정하면, **Then** 기준 루틴과 변경안이 고정되고 필수 퀘스트가 생성된다.
- **Given** 이미 계획·진행·보류 중인 실험, **When** 새 실험을 시작하려 하면, **Then** 기존 실험을 완료 또는 취소하는 행동을 안내한다.
- **Given** 불편함으로 보류 완료한 실험, **When** 다시 시험하면, **Then** 이전 실험에 연결된 새 실험이 생성된다.

## 분석 이벤트

| 이벤트 | 발생 시점 | 속성 |
| --- | --- | --- |
| `comparison_viewed` | 후보 차이 확인 | 추가·교체, 새 기능 수, 중복 수, 정보 부족 여부 |
| `trial_order_viewed` | 후보 순서 확인 | 후보 수, 개인 근거 사용 여부 |
| `experiment_planned` | 계획 확정 | 기간, 변경 의도, 필수 퀘스트 수 |
| `experiment_started` | 첫 사용 기록 | 계획 후 시작까지 걸린 일수 |
| `experiment_paused` | 보류 | 불편 관련 여부 |
| `experiment_cancelled` | 취소 | 구조화된 취소 이유 |
