## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 안정 루틴 버전과 제품·목적·추가 또는 교체 의도가 있는 실험 후보가 있다. 교체라면 제거할 제품과 시간대를 정했다. |
| 입력·행동 | 후보를 열고 추가·유지·제거 제품, 새로 생기거나 겹치거나 사라질 수 있는 기능과 관찰 항목을 확인한다. |
| 시스템 처리 | 안정 루틴을 수정하지 않고 후보를 적용한 가상 루틴을 만든다. 제품과 기능의 추가·중복·교체를 확인된 정규화 정보로 계산하고 당시 루틴·제품·정책 버전을 저장한다. |
| 사용자 결과 | 새 제품이 현재 루틴에서 무엇을 바꾸는지 한눈에 이해한다. |
| 핵심 규칙 | 추가는 제품 하나를 넣고, 교체는 지정 제품 하나를 빼고 같은 위치에 후보를 넣는다. 전성분 전체 차집합보다 목적·기능 중복·개인 경험과 출처가 있는 관찰 항목을 우선한다. 기능이 `충분하다`고 판정하지 않고 사용 목적과 무관한 중복을 사실로 표시한다. |
| 예외·복구 | 후보 저장 당시 비교는 보존하되 현재 안정 루틴이 달라졌으면 실험 시작 전에 최신 기준으로 새 비교를 만든다. 교체 대상이 사라져도 자동 대체하지 않는다. 미확정 정보는 `없음`이 아니라 `정보 부족`이다. |
| 완료 기준 | 추가·교체 결과와 기능 중복·소실을 구분한다. 후보 결과가 섞이지 않는다. 미확정 정보를 단정하지 않는다. 비교 당시 버전을 복원할 수 있다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
