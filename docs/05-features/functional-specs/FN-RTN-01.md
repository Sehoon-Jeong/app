## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 로그인했고 계획·진행·보류 중인 실험이 없다. 카탈로그 제품 또는 확인한 개인 제품을 선택할 수 있다. |
| 입력·행동 | 피부 고민 또는 `잘 모르겠어요`, 아침·저녁 제품·실제 순서와 제품별 빈도를 입력한다. 이 조합을 사용한 기간, 가장 최근 제품 변경과 현재 불편 여부를 답하고 현재 기준으로 삼겠다고 직접 확인한다. |
| 시스템 처리 | 제품·시간대·순서 중복과 빈도 형식을 검증한다. 확인 전에는 초안으로 저장한다. 현재 불편 없음과 사용자 확인이 모두 있으면 사용 시작·최근 변경·제품별 빈도의 입력 수로 정보 수준을 계산해 불변 루틴 버전을 만든다. |
| 사용자 결과 | 확정 시각, 제품 구성·빈도와 기준 정보의 충분·제한·부족 상태를 확인하고 이후 추천·비교의 기준으로 사용한다. |
| 핵심 규칙 | 빈도는 매일·특정 요일·주 N회·필요할 때·잘 모르겠음을 지원한다. 같은 제품은 아침과 저녁에 각각 둘 수 있지만 같은 시간대에 중복할 수 없다. AI가 안정 여부를 판정하지 않는다. 열린 실험이 참조하는 루틴은 종료 전 바꿀 수 없다. |
| 예외·복구 | 기간이 짧거나 사용 시작·최근 변경·빈도를 몰라도 확정을 막지 않고 정보 수준에 반영한다. 현재 불편 있음·잘 모르겠음이면 안정 루틴으로 확정하지 않고 초안을 유지한다. 제품을 찾지 못하면 직접 등록으로 이동한다. 저장 실패 뒤에도 작성 중 입력을 유지한다. |
| 완료 기준 | 빈도를 포함한 루틴을 저장·재조회한다. 현재 불편 없음과 사용자 확인이 없는 입력은 안정 루틴이 되지 않는다. 세 입력 항목으로 충분·제한적·부족을 재현한다. 편집해도 과거 버전과 실험 참조가 보존된다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
