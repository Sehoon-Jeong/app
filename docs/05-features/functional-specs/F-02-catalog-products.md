# F-02 카탈로그·내 화장품

## 1. 사용자가 얻는 결과

사용자는 제품명을 검색하거나 영수증을 촬영해 실제 국내 판매 제품을 자신의 목록에 넣는다. 구매 기록과 실제 루틴을 분리하고, 제품 버전이 불확실할 때는 기록은 남기되 AI 판단에는 사용하지 않는다.

## 2. 제품의 기준 단위

AI와 개인 기록이 참조하는 단위는 `product`가 아니라 `product_version`이다.

| 개념 | 예 | 규칙 |
| --- | --- | --- |
| 제품군 | 아쿠아 하이드라 세럼 | 이름이 유지되는 제품 그룹 |
| 제품 버전 | 2026년 리뉴얼 30 ml | 용량·옵션·판매 시기·포장 단서가 같은 실제 판매본 |
| 내 화장품 | 사용자가 가진 해당 버전 한 개 | 구매와 사용 이력을 연결하는 사용자 소유 항목 |

카탈로그 범위는 한국에서 판매되는 `SKINCARE`, `CLEANSING`, `SUNCARE`다. 메이크업·헤어·향수는 검색 결과에서 제외한다.

## 3. 버전 상태와 사용 가능 범위

| 상태 | 등록 | 메모 | 루틴 추가 | 제품 의견·추천·루틴 AI·Rescue 근거 |
| --- | --- | --- | --- | --- |
| `VERIFIED` | 가능 | 가능 | 가능 | 가능 |
| `UNCERTAIN` | 가능 | 가능 | 가능하나 정보 부족 표시 | 제품 사실 근거로는 불가. 등록·사용 시점 같은 사용자 사실만 사용 |
| `RETIRED` | 기존 기록 조회만 | 가능 | 기존 루틴 조회만 | 과거 시점 분석에만 사용 |

`UNCERTAIN`은 성분이 없다는 뜻이 아니다. 제품 버전을 확정하지 못했다는 뜻이다.

## 4. 제품명 검색과 등록

1. 사용자가 브랜드 또는 제품명 일부를 입력한다.
2. 서버는 브랜드명·정식 제품명에서 검색하고 최대 20개를 관련도 순으로 반환한다.
3. 각 결과는 브랜드, 제품명, 용량·옵션, 대표 이미지, 버전 상태를 표시한다.
4. 사용자가 한 버전을 열면 공식 사용법, 표시 전성분 원문, 확인된 제품 사실, 출처와 확인 시각을 보여준다.
5. `내 화장품에 추가`를 누르면 멱등 키와 함께 `user_product`를 만든다.
6. 새 항목은 `UNUSED`로 시작하며 현재 루틴을 바꾸지 않는다.
7. 루틴 편집 중 들어온 경우 등록 성공 후 같은 편집안으로 돌아가고 새 항목을 선택 가능 상태로 보여준다.

### 검색 결과가 없을 때

- 사용자가 입력한 이름, 선택 입력인 구매일·용량·포장 단서로 검수 요청을 만든다.
- 해커톤 범위에서는 `RECEIVED`까지만 제공한다.
- 사용자는 입력 이름만 가진 `UNCERTAIN` 내 화장품을 등록할 수 있다.
- 검수 전에도 실제 사용을 기록하기 위해 루틴에는 넣을 수 있다. 다만 AI가 해당 제품의 성분·기능·사용법을 안다고 설명하지 않으며 모든 분석에 `제품 버전 정보 부족`을 표시한다.

## 5. 영수증 OCR

### 입력

- 한 번에 이미지 1개
- 지원 형식과 용량은 배포 설정으로 제한하되 검증 실패는 업로드 전에 표시
- AI로 보내는 범위는 영수증 이미지뿐이며 다른 사용자 메모·루틴은 포함하지 않음

### 흐름

1. 원본을 Object Storage에 저장하고 `receipt_upload`와 `RECEIPT_OCR` job을 만든다.
2. 저장 트랜잭션을 끝낸 뒤 AI가 줄별 원문 위치와 브랜드·제품명·용량 후보를 추출한다.
3. 서버가 후보 문자열을 카탈로그 버전과 연결한다.
4. 완료 화면은 영수증 한 줄마다 원문, 후보 목록, `다른 제품 찾기`, `제외`를 보여준다.
5. 사용자가 모든 포함 행을 확정한 뒤 한 번에 제출한다.
6. 확정된 각 행마다 `user_product(UNUSED)`를 만들고 해당 `receipt_item`과 연결한다.

OCR은 제품을 자동 확정하지 않는다. `include=true`인 행은 반드시 `productVersionId`가 있어야 한다.

## 6. 내 화장품 화면

같은 `user_product`가 여러 묶음에 나타날 수 있다. 묶음은 재고 상태가 아니라 현재·안정 루틴 포함 관계다.

| 묶음 | 포함 조건 | 빈 상태 행동 |
| --- | --- | --- |
| 미사용 화장품 | 현재 루틴과 마지막 안정 루틴 어디에도 없음 | 새 화장품 추가 |
| 현재 루틴 | 현재 루틴 item에 포함 | 현재 루틴 보기·수정 |
| 마지막 안정 루틴 | stable pointer의 routine item에 포함 | 해당 루틴 상세 보기 |

제품 상세에는 다음을 표시한다.

- 정확한 제품 버전과 확인 상태
- 공식 제품 사실·표시 전성분·출처·확인 시각
- 현재 메모
- 포함됐던 루틴 기록과 루틴 전체 결과
- 가장 최근 제품 AI 분석과 실패·재시도 상태

루틴 결과를 제품 단독 결과처럼 표현하지 않는다.

## 7. 메모·삭제·중복

- 메모는 1,000자 이하이며 최신 메모 하나를 표시한다.
- AI 요청의 `includeMemo=true` 또는 사용자의 명시적 동의가 있을 때만 해당 제품 메모를 전송한다.
- 같은 사용자가 같은 제품 버전을 다시 추가하면 기존 항목을 보여준다. 사용자가 별도 보유품으로 추가하겠다고 확인한 경우에만 중복 생성한다.
- 현재 루틴에 포함된 제품 삭제는 `409 PRODUCT_IN_CURRENT_ROUTINE`으로 막고 루틴 편집으로 이동시킨다.
- 안정 루틴에만 포함된 제품은 내 화장품에서 삭제할 수 있지만 과거 routine item과 제품 버전 기록은 보존한다.
- 삭제된 내 화장품은 새 루틴 선택 목록과 AI의 현재 보유품 입력에서 제외한다.

## 8. 제품 사실과 출처

- 우선순위: 브랜드·제조사 → 정부·규제기관 → 공식 성분 DB → 원 논문.
- 블로그·리뷰·커뮤니티는 제품 사실과 AI 판단 근거로 저장하지 않는다.
- `product_fact`는 사실 유형, 원문, 적용 버전, 출처, 확인 시각을 함께 가진다.
- 표시 전성분은 원문 순서를 보존한다. 성분 이름 동일성만 사전화하며 피부 영향 enum은 두지 않는다.
- 가격·판매처는 확인 시각과 함께 참고로만 보여주며 의견·추천 정렬 입력에서 제외한다.

## 9. 실패·예외 계약

| 상황 | 사용자 결과 | 재시도·대체 경로 |
| --- | --- | --- |
| OCR 실패 | 원본과 실패 상태 표시 | 같은 원본 재시도 또는 제품명 검색 |
| OCR 일부 미일치 | 맞은 행은 유지, 해당 행만 미확정 | 직접 제품 검색 또는 제외 |
| 제품 검색 0건 | 검색어 유지 | 검수 요청·불확실 등록 |
| 버전 불확실 | `확인 중` 표시 | 포장·구매일·용량 단서 추가 |
| 더블 탭·네트워크 재시도 | 동일 응답 재사용 | 새 보유품 중복 생성 금지 |
| 다른 사용자 항목 접근 | 찾을 수 없음 | 정보 노출 없음 |

## 10. 상태·API·데이터 변화

| 행동 | API | 주요 데이터 |
| --- | --- | --- |
| 제품 검색·상세 | `GET /products`, `GET /products/{productVersionId}` | catalog read |
| 검수 요청 | `POST /catalog-review-requests` | `catalog_review_request` |
| 내 화장품 조회·등록·삭제 | `GET/POST /me/products`, `DELETE /me/products/{myProductId}` | `user_product` |
| 메모 저장 | `PUT /me/products/{myProductId}/memo` | `product_memo` |
| 영수증 업로드·확인 | `POST /receipts`, `GET /receipts/{receiptId}`, `POST /receipts/{receiptId}/confirm` | receipt, job, user product |

## 11. 수용 시나리오

1. **Given** 검증된 제품 버전, **When** 등록하면, **Then** 미사용 화장품에만 추가되고 현재 루틴은 그대로다.
2. **Given** 불확실 제품, **When** 루틴에 추가하면, **Then** 실제 사용 조건은 저장되지만 제품 사실을 이용한 AI 판단은 차단되고 정보 부족이 표시된다.
3. **Given** OCR 후보 세 줄 중 두 줄만 확정, **When** 제출하면, **Then** 두 제품만 한 번씩 등록된다.
4. **Given** 현재 루틴 제품, **When** 삭제하면, **Then** 제품은 남고 루틴 편집 진입을 제공한다.
5. **Given** 사용자 A의 내 화장품 ID, **When** 사용자 B가 조회하면, **Then** 존재 여부를 구분하지 않는 404를 받는다.
