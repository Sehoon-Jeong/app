## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 실험이 진행 또는 보류 상태이고 사용 기간·관찰·중단·Rescue를 요약할 수 있다. |
| 입력·행동 | 문제없이 사용·불편함·보류·판단 어려움 중 결과를 직접 선택하고 메모를 남긴다. 문제없이 사용한 경우에만 안정 루틴 반영 여부와 실제 순서를 확인한다. |
| 시스템 처리 | 결과 저장·완료 전환·LAB 기록 생성을 중복 안전한 한 작업으로 처리한다. 동의한 경우 추가·교체 규칙에 맞는 새 불변 안정 루틴 버전을 만든다. |
| 사용자 결과 | 자신의 판단으로 실험을 완료하고 원할 때만 검증한 제품을 현재 안정 루틴에 반영한다. |
| 핵심 규칙 | 서비스가 결과를 대신 고르지 않는다. 네 결과를 의학적 원인이나 치료 결과로 해석하지 않는다. 문제없이 사용과 명시적 동의가 모두 있어야 루틴을 바꾼다. 이전 루틴과 결과를 수정하지 않는다. |
| 예외·복구 | 불편함·보류·판단 어려움은 안정 루틴을 바꾸지 않는다. 문제없이 사용했어도 동의가 없으면 경험만 저장한다. 계획과 실제 순서가 다르면 확정 전 수정·확인한다. 중복 제출로 결과·루틴이 늘어나지 않는다. |
| 완료 기준 | 결과와 실제 기간·관찰을 함께 저장한다. 허용된 경우에만 새 루틴을 만든다. 이전 버전과 과거 참조를 보존한다. 중복 요청에도 결과·전환·LAB 기록이 각각 하나다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
