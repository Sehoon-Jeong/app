## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 실험이 진행 또는 보류 상태이고 사용 기간·관찰·중단·Rescue를 요약할 수 있다. |
| 입력·행동 | 불편 없음·있음·잘 모르겠음, 목적에 도움·변화 없음·잘 모르겠음, 안정 루틴에 추가·중단·보류·재시험을 각각 선택하고 메모를 남긴다. Rescue가 있었다면 기존 안정 루틴 제품을 모두 계속 사용·일부 중단·모두 중단·잘 모르겠음으로 답한다. |
| 시스템 처리 | 실제 기간·사용 횟수·필수 관찰·다른 제품 변경으로 기록 완성도를 계산하고 결과 저장·완료 전환·LAB 기록을 중복 안전하게 처리한다. 허용된 경우만 새 불변 루틴 버전을 만든다. |
| 사용자 결과 | 불편, 목적 체감과 다음 결정을 구분해 실험을 완료하고 원할 때만 제품을 안정 루틴에 반영한다. |
| 핵심 규칙 | 서비스가 결과를 대신 고르거나 효능·원인으로 해석하지 않는다. 불편 없음과 안정 루틴 추가 결정을 모두 확인해야 루틴을 바꾼다. 짧거나 다른 변수가 섞인 결과도 저장하되 제한된 근거로 표시한다. |
| 예외·복구 | 불편 있음·잘 모르겠음 또는 중단·보류·재시험 결정은 안정 루틴을 바꾸지 않는다. 계획과 실제 순서가 다르면 결과에 이탈로 남긴다. 완료 후 후속 관찰은 원래 결과를 수정하지 않는다. |
| 완료 기준 | 세 결과와 실제 기간·횟수·관찰 완성도·다른 변경을 저장하고, Rescue가 있으면 기존 루틴 사용 상태도 저장한다. 허용된 경우에만 새 루틴을 만든다. 중복 요청에도 결과·전환·LAB 기록이 각각 하나다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
