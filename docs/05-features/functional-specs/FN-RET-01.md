## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 이전 다음 결정이 보류 또는 재시험이고, 사용자가 현재 안정 상태를 직접 확인했으며 다른 열린 실험이 없다. |
| 입력·행동 | 이전 결과·부족 정보·미완료 관찰을 확인하고 현재 안정 루틴으로 다시 비교한 뒤 새 기간과 관찰 계획을 확정한다. |
| 시스템 처리 | 이전 실험을 수정하지 않고 원본을 참조하는 새 실험을 만든다. 현재 안정 루틴으로 비교를 다시 계산하고 부족했던 관찰 항목을 새 계획에 포함한다. |
| 사용자 결과 | 과거 기록을 잃지 않고 보류 제품을 별도의 새 실험으로 다시 시험한다. |
| 핵심 규칙 | AI가 안정 상태를 판정하지 않는다. 새 실험은 이전 실험과 연결되고 사용자당 열린 실험 하나 원칙을 지킨다. 불편함 결과를 일반 경로에서 자동 재시험 권유하지 않는다. |
| 예외·복구 | 안정 확인이 없으면 계획을 확정하지 않는다. 열린 실험이 있으면 재시험 후보까지만 저장하고 시작을 막는다. 이전 결과와 Rescue는 새 결과로 덮어쓰지 않는다. |
| 완료 기준 | 보류·재시험 결정에서만 재시험 경로가 열린다. 안정 확인을 요구한다. 새 실험이 원본과 연결되고 현재 루틴으로 재비교된다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
