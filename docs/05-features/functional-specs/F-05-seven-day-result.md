# F-05 7일 결과

## 목적

문제가 생긴 사람뿐 아니라 별일 없이 사용한 사람의 루틴도 개인 근거로 남긴다.

## 일정

- 루틴을 저장한 현지 날짜를 `DAY 1`로 본다.
- `DAY 7 00:00`에 앱 안 알림과 홈의 가장 중요한 행동을 만든다.
- 7일은 임상 판정 기간이 아니라 MVP 운영 규칙이다.
- 사용자는 불편하면 언제든 바로 Rescue를 시작한다.

## 7일 결과 대화

1. 앱은 평가 대상 루틴의 날짜, 아침·저녁 제품·순서·빈도를 먼저 보여준다.
2. `실제로도 이 기록과 비슷하게 사용했나요?`를 묻는다.
3. `예`면 전반적으로 `불편 없음`, `불편함`, `더 써봐야 함`을 묻는다.
4. 불편 없음: 결과를 저장하고 해당 버전을 마지막 안정 루틴으로 지정한다.
5. 불편함: 지금까지의 대화를 유지한 채 Rescue 질문을 이어 붙인다.
6. 더 써봐야 함: 같은 루틴의 7일을 다시 시작한다. 안정 승급은 하지 않는다.
7. 실제 사용이 다름: 어떤 부분이 달랐는지 루틴 편집에서 고치고 새 버전·새 7일을 만든다. 기존 버전에 안정/불편 결과를 붙이지 않는다.

## 7일 전 변경

루틴을 편집하려는 시점이 DAY 1~6이면 바텀시트 하나만 보여준다.

- `지금까지 결과 남기기`: 전반적으로 불편 없음/있음/모르겠음을 저장한다. 짧은 기간과 변경 직전 기록임을 표시해 낮은 신뢰도로만 재사용한다.
- `기록 없이 바꾸기`: 아무 결과도 추정하지 않고 편집을 계속한다.

응답 뒤 새 루틴을 저장하면 새 7일이 시작된다. 같은 질문을 나중에 다시 강요하지 않는다.

## 데이터 규칙과 완료 조건

- `불편 없음`은 해당 루틴 묶음에 대한 결과이며 각 제품의 단독 적합성을 뜻하지 않는다.
- 미응답은 불편 없음으로 처리하지 않는다.
- 결과에는 질문 대상 버전, 실제 사용 일치 여부, 응답 시각, 예정일 대비 지연, 선택 결과를 남긴다.
- 같은 루틴 결과를 여러 번 제출해도 하나만 반영한다.

연결 요구사항: OBS-01~08, RTN-03, HIS-01, NOT-01
