## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 최신 비교 결과가 있는 후보 하나를 골랐고 다른 열린 실험이 없다. |
| 입력·행동 | 사용 시간대·순서·시작 예정일을 확인하고 7~28일 사이 기간, 관찰 항목과 동시에 바꾸지 않을 제품을 확정한다. |
| 시스템 처리 | 선택 제품·기준 루틴·비교 결과를 고정 참조하는 실험과 첫 사용·24시간·중간·종료 퀘스트를 만든다. 실제 첫 사용 시각에 맞춰 이후 일정과 종료 시점을 다시 계산한다. |
| 사용자 결과 | 한 제품을 언제 어디에 사용하고 무엇을 관찰할지 아는 상태로 실험을 시작한다. |
| 핵심 규칙 | 사용자당 계획·진행·보류 중 실험은 하나만 둔다. 기본은 14일이며 효능·안전 판단 기준이 아니다. 첫 사용 후에는 제품·기준 루틴·기간을 바꾸지 않는다. 상태와 사용 방식 이탈을 이력으로 남긴다. |
| 예외·복구 | 열린 실험이 있으면 새 시작을 차단한다. 첫 사용 전 기간 변경은 일정을 다시 계산한다. 여행·분실처럼 불편과 무관한 보류만 같은 실험으로 재개한다. 불편 후 재시험은 안정 확인 뒤 새 연결 실험으로 만든다. |
| 완료 기준 | 계획과 필수 퀘스트가 함께 저장된다. 늦게 시작해도 실제 첫 사용부터 전체 기간을 적용한다. 동시 요청에도 열린 실험은 하나다. 허용되지 않은 상태 전환을 거부한다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
