## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 진행 중 실험에 예정 퀘스트가 있고 브라우저가 알림을 지원한다. |
| 입력·행동 | 알림 목적과 정보 범위를 확인한 뒤 알림 받기를 선택하고 브라우저 권한을 허용·거부·철회한다. |
| 시스템 처리 | 동의한 구독에만 퀘스트당 예정 알림과 놓침 알림을 각각 한 번까지 전송한다. 클릭하면 인증 뒤 해당 인앱 퀘스트로 이동한다. |
| 사용자 결과 | 제품명이나 피부 상태가 노출되지 않는 안내로 관찰 시점을 놓치지 않는다. |
| 핵심 규칙 | 설명 전에 권한을 요청하지 않는다. 본문과 전송 로그에 민감 정보를 넣지 않는다. 알림은 인앱 상태의 보조 수단이며 클릭·허용에 LAB 보상을 주지 않는다. |
| 예외·복구 | 권한 거부·미지원·구독 만료·전송 실패에도 인앱 퀘스트는 동작한다. 완료·건너뜀·취소 퀘스트의 예약 알림을 막는다. 로그아웃 상태라면 인증 후 원래 퀘스트로 돌아간다. |
| 완료 기준 | 명시적 선택 뒤에만 권한을 요청한다. 민감 정보 없는 중복 방지 알림을 보낸다. 실패 상태에서도 인앱 기록이 가능하다. 중지된 퀘스트에 알림이 가지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
