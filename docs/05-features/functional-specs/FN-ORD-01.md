## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 최신 비교 결과가 있는 실험 후보가 하나 이상 있다. |
| 입력·행동 | 추천·검색으로 저장한 후보를 같은 목록에서 보고 먼저 시험하는 이유, 달라지는 점, 뒤로 둔 이유와 모르는 점을 확인해 하나를 선택한다. |
| 시스템 처리 | 추천과 동일한 결정표로 목적 관련성, 목적과 무관한 중복·변수 수, 정보 확인, 관련 개인 경험·기록 완성도와 안정 정렬을 적용한다. AI는 계산 결과를 설명할 뿐 순서를 바꾸지 않는다. |
| 사용자 결과 | 여러 후보 중 무엇을 먼저 시험하면 변수를 분명하게 확인할 수 있는지 이해한다. |
| 핵심 규칙 | 사용자가 보는 추천과 실험 순서는 하나다. 제안은 잘 맞는 제품 순위가 아니라 시험하기 좋은 순서다. 과거 불편 결과는 영구 제외 조건이 아니며 기록 완성도와 함께 반대 근거로 표시한다. |
| 예외·복구 | 기준 루틴이 달라진 후보는 제외하고 재비교한다. 근거가 같으면 확인 수준과 안정 정렬 규칙으로 결과를 고정한다. 개인 이력이 없으면 일반 근거만 사용한다. |
| 완료 기준 | 모든 후보의 순서와 비교 가능한 이유가 보인다. 같은 입력·정책 버전에서 같은 결과가 나온다. 과거 불편과 낮은 근거를 숨기지 않는다. 적합성·구매 보장 표현을 쓰지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
