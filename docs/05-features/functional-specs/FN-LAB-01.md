## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 실험에 필수 관찰 퀘스트가 생성됐다. |
| 입력·행동 | 필수 관찰을 저장하고 완료 수·전체 수, 연구 기록 도장과 남은 행동을 확인한다. |
| 시스템 처리 | 완료한 필수 퀘스트 수를 생성된 필수 퀘스트 수로 나눠 진행도를 계산한다. 종료 관찰과 최종 결과까지 있어야 100%로 만든다. |
| 사용자 결과 | 현재 실험에서 끝낸 일과 다음 행동을 LAB 안에서 이해한다. |
| 핵심 규칙 | 선택 관찰과 예정 밖 기록은 분모·분자에서 제외한다. 건너뜀은 완료가 아니다. 관찰 수정·재전송으로 보상을 중복 생성하지 않는다. 긍정·부정 결과를 동등하게 인정한다. |
| 예외·복구 | 취소 실험은 진행 이력만 남기고 완료 연구 보상을 만들지 않는다. 로그인·접속·알림 클릭·화면 체류는 진행도와 보상을 올리지 않는다. |
| 완료 기준 | 필수·선택·건너뜀 조합에 맞는 진행도가 나온다. 중복 도장이 생기지 않는다. 최종 결과 전에는 100%가 아니다. 결과 방향이 보상량을 바꾸지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
