# F-08 AI 조사·비동기 작업

## 역할 분리

### AI가 맡는 일

- 온보딩, 제품 목적, 불편 표현과 영수증 문장을 구조화한다.
- 답을 크게 바꾸는 정보가 없을 때만 추가 질문을 만든다.
- OpenAI 웹 검색으로 현재 질문과 관련된 공식·1차 출처를 찾는다.
- 제품 의견, 추천, 루틴 배치와 Rescue 제안을 설명한다.
- 자연어 개인 맥락을 다음 대화에서 기억한다.

### 서버가 맡는 일

- 인증과 사용자 데이터 소유권을 확인한다.
- 실제 카탈로그 제품 ID와 버전을 확정한다.
- 현재 루틴, 안정 루틴과 버전 차이를 계산한다.
- AI 출력 JSON schema, 인용 출처, 참조 ID와 금지 표현을 검사한다.
- 사용자가 확정한 상태 전이만 저장한다.

## 검색 규칙

1. AI 요청에는 질문, 제품 버전 단서, 필요한 최소 개인 맥락, 허용 출처 종류를 보낸다.
2. OpenAI API가 같은 작업에서 웹을 검색하고 URL·제목·기관·게시일·관련 발췌·주장을 구조화해 반환한다.
3. 서버는 URL 허용 정책, 제품 버전 연결과 필수 필드를 검증한다.
4. 완제품 사람 대상 연구와 원료 연구를 구분한다.
5. 원료 연구를 완제품 효과로 바꾸어 말하지 않는다.
6. 검증된 근거와 결과의 입력 스냅샷을 저장한다.

## 비동기 작업

대상은 영수증 OCR, 추천, 제품·성분 조사, 루틴 분석과 Rescue 분석이다.

상태는 `QUEUED → RUNNING → SUCCEEDED | FAILED`다. 동일 사용자·작업 종류·입력 해시에 열린 작업이 있으면 재사용한다. 재시도는 이전 작업을 덮지 않고 `retry_of_job_id`로 연결한다.

## 실패 처리

- AI 호출 전에 사용자 쓰기를 커밋한다.
- 실패 화면은 무엇이 저장됐고 무엇만 실패했는지 말한다.
- 고정 설명 또는 직접 입력으로 완료 가능한 흐름은 계속한다.
- 재시도 버튼은 중복 결과를 만들지 않는다.
- 원문 프롬프트에 필요하지 않은 개인 메모와 식별자를 포함하지 않는다.

## 완료 조건

- 출력 schema 위반, 존재하지 않는 제품, 잘못된 사용자 참조와 출처 없는 주장을 거절한다.
- 모든 결과가 사용 모델, prompt version, 입력 해시, 시작·완료 시각, 실패 코드를 남긴다.
- DB 쓰기 트랜잭션 안에서 AI나 Object Storage를 기다리지 않는다.
