## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 안정 루틴이 확정됐고 추천 카드 또는 검색 결과에서 제품을 선택했다. 목적과 추가·교체 의도가 있다. |
| 입력·행동 | 제품을 `실험 후보로 저장`하고 목적·변경 방식·교체 대상을 확인한다. |
| 시스템 처리 | 제품 버전, 안정 루틴 버전, 목적, 변경 의도, 교체 대상과 유입 경로를 함께 저장한다. 동일한 미완료 후보의 중복 생성을 막는다. |
| 사용자 결과 | 추천 제품과 직접 찾은 제품을 같은 목록에서 보고 비교 또는 실험 계획으로 이동한다. |
| 핵심 규칙 | 추천 여부는 유입 경로일 뿐 후보 자격을 구분하지 않는다. 추천 후보는 당시 근거와 정책 버전을 추적한다. 직접 찾은 제품도 확인된 정보가 있으면 실험할 수 있다. |
| 예외·복구 | 안정 루틴이 바뀌면 기존 후보를 보존하되 `다시 비교 필요`로 표시한다. 교체 대상이 없으면 저장을 막는다. 부족한 제품 정보는 부족 상태로 명시한다. |
| 완료 기준 | 두 유입 경로를 같은 목록에서 구분한다. 저장 당시 루틴과 변경 방식을 복원한다. 중복 후보가 생기지 않는다. 후보 삭제가 이미 시작한 실험을 훼손하지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
