# F-07 홈·기록·알림

## 1. 사용자가 얻는 결과

P0 홈은 사용자가 지금 해야 할 행동 하나와 현재 루틴이 마지막 안정 루틴에서 어떻게 달라졌는지를 보여준다. 전체 타임라인과 알림함은 이 핵심 비교가 유용한 뒤 확장한다.

## 2. 우선순위 범위

| 우선순위 | 결과 | 요구사항 |
| --- | --- | --- |
| P0 | 홈의 현재 행동 하나, 현재·마지막 안정 루틴 비교 | HIS-02 |
| P1 | 전체 루틴 타임라인·제품별 이력·앱 안 알림함 | HIS-01, HIS-03, NOT-01~02 |
| P2 | 없음 | - |

## 3. P0 계약

### 3.1 홈의 주 행동

홈은 별도 notification 행 없이 열린 Rescue, assessment schedule과 ACTIVE 루틴을 조회해 가장 높은 행동 하나를 고른다.

| 순위 | 조건 | 주 행동 |
| --- | --- | --- |
| 1 | 열린 Rescue | `Rescue 이어가기` |
| 2 | 기한이 지난 DAY 7 결과 | `7일 결과 남기기` |
| 3 | 오늘이 DAY 7 | `7일 결과 남기기` |
| 4 | 현재 루틴이 있고 DAY 7 전 | 진행일과 `불편함이 생겼어요` |
| 5 | 현재 루틴과 마지막 안정 루틴이 같음 | `이거 사볼까?` |
| 6 | 내 화장품은 있으나 루틴이 없음 | `첫 루틴 만들기` |
| 7 | 내 화장품도 없음 | `새 화장품 추가` |

같은 순위에서는 기한이 오래 지난 것, 생성 시각이 오래된 것, ID 순으로 고른다. 보조 진입점은 함께 둘 수 있지만 주 행동과 같은 강도로 강조하지 않는다.

### 3.2 현재·마지막 안정 루틴 비교

서버가 두 스냅샷에서 아래 변경을 계산한다. AI가 비교 사실을 만들지 않는다.

| 변경 | 표시 |
| --- | --- |
| `PRODUCT_ADDED` | 추가된 제품과 시간대 |
| `PRODUCT_REMOVED` | 빠진 제품과 시간대 |
| `PERIOD_CHANGED` | 아침·저녁 이동 |
| `ORDER_CHANGED` | 이전·이후 순서 |
| `FREQUENCY_CHANGED` | 이전·이후 빈도 |

안정 루틴이 없으면 현재 루틴만 보여주고 `아직 비교할 안정 루틴이 없어요`라고 말한다. 변경이 없으면 `현재 루틴이 마지막 안정 루틴과 같아요`라고 표시한다.

### 3.3 P0 API·실패·수용

| 행동 | API | 데이터 변화 |
| --- | --- | --- |
| 홈 조회 | `GET /me/home` | 없음 |
| 현재·안정 비교 | `GET /me/routines/compare` | 없음 |

- 일부 AI 설명이 실패해도 저장된 루틴과 서버 비교는 표시한다.
- 다른 사용자 routine ID는 존재하지 않는 것처럼 처리한다.
- 열린 Rescue와 DAY 7이 함께 있으면 Rescue가 주 행동이다.
- 비교는 중간 버전을 추정하지 않고 선택한 두 스냅샷의 실제 차이만 반환한다.

## 4. P1 계약 · 전체 기록

### 4.1 루틴 타임라인

최신 버전부터 버전·시작일·생성 이유·제품 수·현재/안정 여부·결과를 보여준다. 상세에는 아침·저녁 제품, 순서, 빈도, schedule과 assessment, 안정 승급, 연결된 Rescue와 적용된 다음 루틴을 표시한다.

과거 버전은 읽기 전용이다. 다시 사용하려면 구성을 복사한 새 ACTIVE 버전을 만든다.

### 4.2 제품별 기록

- 해당 `user_product`가 포함된 루틴만 최신순으로 보여준다.
- 루틴 전체 결과, 조기 결과, 결과 없음의 범위를 구분한다.
- 제품 단독 결과가 없으면 단독 결과가 없다고 말한다.
- 삭제된 내 화장품도 과거 루틴에서는 당시 제품 정보로 보존한다.

### 4.3 앱 안 알림

| 종류 | 생성 시점 | 중복 기준 |
| --- | --- | --- |
| `ASSESSMENT_DUE` | schedule 기한 도래 | schedule/type |
| `AI_JOB_SUCCEEDED` | 확인할 AI 작업 완료 | job/type |
| `AI_JOB_FAILED` | 재시도 가능한 작업 실패 | job/type |

읽음은 사용자가 알림을 열었다는 뜻일 뿐 결과 제출이나 AI 결과 동의가 아니다. P1은 푸시·이메일·문자를 포함하지 않는다.

P1 API는 `GET /me/routines/history`, `GET /me/routines/{routineId}`, `GET /notifications`, `POST /notifications/{notificationId}/read`를 추가한다.

연결 요구사항: HIS-01~03, NOT-01~02, OBS-01
