# F-07 기록·홈·알림

## 1. 사용자가 얻는 결과

사용자는 현재 루틴이 어떻게 바뀌어 왔고 각 버전에서 어떤 결과를 남겼는지 다시 본다. 홈은 현재 상태에서 가장 중요한 행동 하나를 제시하고 앱 안 알림은 7일 결과와 비동기 작업 완료를 놓치지 않게 한다.

## 2. 루틴 기록

### 2.1 목록

최신 `versionNo` 순으로 다음을 표시한다.

- 버전과 시작일
- 생성 이유: `직접 변경` 또는 `Rescue 제안 적용`
- 아침·저녁 제품 수
- 현재 루틴 여부
- 마지막 안정 루틴 여부
- 7일 결과 또는 `아직 결과 없음`
- AI 분석 상태

동일 버전의 연장 assessment가 여러 개면 가장 최근 round의 결과를 요약하고 전체 round 수를 표시한다.

### 2.2 상세

- 아침·저녁 제품명, 순서, 빈도
- DAY 1, 최초 due, 연장 due
- 조기 결과와 final 결과 전체
- 안정 승급 여부와 당시 시각
- 연결된 Rescue와 적용한 다음 routine
- 루틴 전체·제품별 AI 분석과 각 근거

과거 버전은 읽기 전용이다. 수정하려면 해당 버전을 복사해 새 current로 저장한다.

### 2.3 버전 비교

사용자가 소유한 두 버전을 선택하면 서버가 다음 change를 계산한다.

| change type | 표시 |
| --- | --- |
| `PRODUCT_ADDED` | 어느 시간대에 어떤 제품이 추가됐는지 |
| `PRODUCT_REMOVED` | 어느 시간대에서 빠졌는지 |
| `PERIOD_CHANGED` | 아침↔저녁 이동 |
| `ORDER_CHANGED` | 이전·이후 위치 |
| `FREQUENCY_CHANGED` | 이전·이후 빈도 원문 |

변경이 없으면 빈 목록과 `두 버전의 기록이 같습니다`를 반환한다. AI가 비교 사실을 만들지 않는다.

## 3. 제품에서 사용 기록 보기

- 제품 상세의 `사용 기록`은 해당 `user_product`가 포함된 routine version을 최신순으로 보여준다.
- 각 항목은 루틴 전체 결과인지, 조기 결과인지, 결과가 없는지 명시한다.
- 같은 제품 버전이라도 다른 `user_product`의 기록을 합치지 않는다.
- 제품 단독 결과가 없으면 `이 제품만 따로 사용한 결과는 아직 없어요`라고 표시한다.
- 삭제된 내 화장품도 과거 루틴 상세에서는 당시 제품 버전으로 표시한다.

## 4. 홈 상태 선택 규칙

홈의 주 행동은 아래 후보 중 가장 높은 우선순위 하나다. 같은 우선순위가 여러 개면 `기한이 오래 지난 것 → 생성 시각이 오래된 것 → ID` 순이다.

| 순위 | 조건 | 주 행동 |
| --- | --- | --- |
| 1 | 열린 Rescue가 있음 | `Rescue 이어가기` |
| 2 | due가 지난 미응답 assessment | `7일 결과 남기기` |
| 3 | 오늘 due인 미응답 assessment | `7일 결과 남기기` |
| 4 | 사용자 행동으로 시작한 AI job이 실패 | `AI 분석 다시 시도` |
| 5 | 현재 루틴이 있고 due 전 | DAY 진행 현황, `불편함이 생겼어요` |
| 6 | 현재 루틴이 마지막 안정 루틴과 같음 | `이거 사볼까?`, `제품 추천받기` |
| 7 | 내 화장품은 있으나 루틴이 없음 | `첫 루틴 만들기` |
| 8 | 내 화장품도 없음 | `새 화장품 추가` |

보조 진입점은 함께 표시할 수 있지만 주 행동과 같은 시각적 강도를 갖지 않는다. Rescue에서 `RECORD_ONLY`를 선택했다면 current 카드에 `Rescue 기록 있음 · 루틴 변경 없음`을 표시하되 열린 Rescue로 취급하지 않는다.

## 5. 앱 안 알림

| type | 생성 시점 | target | 중복 키 |
| --- | --- | --- | --- |
| `ASSESSMENT_DUE` | 최초 DAY 7 due 도래 | routine + round | routine/round/type |
| `EXTENDED_ASSESSMENT_DUE` | 연장 due 도래 | routine + round | routine/round/type |
| `AI_JOB_SUCCEEDED` | 사용자 확인이 필요한 AI job 성공 | job 결과 | job/type |
| `AI_JOB_FAILED` | 재시도 가능한 job 실패 | job | job/type |

- 푸시·이메일·문자·브라우저 알림 권한은 MVP에서 사용하지 않는다.
- 읽음은 `readAt`만 기록하며 assessment, 불편 없음, AI 결과 확인으로 해석하지 않는다.
- target이 삭제되거나 접근할 수 없으면 알림 상세 대신 안전한 빈 상태를 열고 알림 자체는 읽음 처리할 수 있다.
- job 성공 알림은 화면에서 이미 결과를 확인했다면 만들지 않거나 즉시 읽음 처리한다.

## 6. 빈 상태와 오류

| 화면 | 빈 상태 | 행동 |
| --- | --- | --- |
| 루틴 기록 | 루틴 0개 | 첫 루틴 만들기 |
| 제품 사용 기록 | 해당 제품 포함 이력 0개 | 현재 루틴에 추가 |
| 비교 | 선택 가능한 버전 1개 이하 | 새 루틴 저장 후 비교 가능 안내 |
| 알림 | 알림 0개 | 별도 행동 없이 홈 이동 |

다른 사용자 routine·notification ID는 존재하지 않는 것과 같이 처리한다. 루틴 목록 일부의 AI 분석이 실패해도 저장된 루틴·결과는 정상 표시한다.

## 7. 상태·API·데이터 변화

| 행동 | API | 데이터 변화 |
| --- | --- | --- |
| 루틴 목록·상세 | `GET /me/routines/history`, `GET /me/routines/{routineId}` | 없음 |
| 루틴 비교 | `GET /me/routines/compare` | 없음 |
| 알림 목록 | `GET /notifications` | 없음 |
| 알림 읽음 | `POST /notifications/{notificationId}/read` | `readAt` 최초 1회 설정 |

## 8. 수용 시나리오

1. **Given** 열린 Rescue와 overdue assessment가 함께 있을 때, **When** 홈을 열면, **Then** Rescue 이어가기가 주 행동이다.
2. **Given** v2와 v4, **When** 비교하면, **Then** 중간 v3가 아니라 두 스냅샷의 실제 차이만 반환한다.
3. **Given** 알림을 읽음, **When** 결과를 제출하지 않으면, **Then** 홈의 due 행동은 유지된다.
4. **Given** 삭제된 내 화장품이 과거 루틴에 포함, **When** 상세를 열면, **Then** 당시 제품 정보와 결과를 볼 수 있다.
5. **Given** 동일 due 생성 작업이 재실행, **When** 알림을 만들면, **Then** dedupe key로 한 건만 존재한다.
