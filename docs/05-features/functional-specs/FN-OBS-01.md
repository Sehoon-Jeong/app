## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 한 제품의 실험 계획에 시작·종료일과 관찰 항목이 있다. |
| 입력·행동 | 첫 사용, 24시간 후, 중간, 종료 시점에 변화 없음·편안함/개선·불편함·잘 모르겠음·사용하지 않음 중 하나를 남긴다. 첫 사용·중간·종료에는 실제 사용과 실험 제품 외의 화장품 변경 여부를 답하거나 기억나지 않으면 건너뛴다. |
| 시스템 처리 | 첫 사용 시각을 실제 시작으로 저장하고 이후 세 퀘스트를 계산한다. 다른 화장품 변경이 있으면 제품·시점을 사건으로 남기고 기록 완성도를 낮춘다. 메모 AI 구조화는 사용자가 요청한 경우에만 실행한다. |
| 사용자 결과 | 매일 일기를 쓰지 않고 판단에 필요한 시점의 기록을 남긴다. |
| 핵심 규칙 | 필수 퀘스트는 네 종류다. 실제 관찰 시각과 입력 시각을 구분한다. 다른 변경이 있어도 실험을 자동 폐기하지 않는다. AI 실패나 미사용에도 원래 메모로 완료한다. 보류·재개 시 미완료 퀘스트만 이동한다. |
| 예외·복구 | 미래 관찰은 저장하지 않는다. 놓친 기록은 뒤늦게 입력할 수 있고, 기억하지 못한 건너뜀은 완료가 아니라 데이터 부족으로 남긴다. 관찰 기간을 효능·안전 기준으로 표현하지 않는다. |
| 완료 기준 | 실제 시작을 기준으로 일정이 계산된다. 같은 퀘스트 응답과 변경 사건이 중복되지 않는다. 사용하지 않음·건너뜀을 피부 결과로 변환하지 않는다. 다른 변경이 기록 완성도와 이후 근거에 반영된다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
