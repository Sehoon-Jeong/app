# F-04 루틴·AI 배치

## 1. 사용자가 얻는 결과

사용자는 실제로 쓰는 화장품 조합을 아침·저녁, 바르는 순서와 빈도로 저장한다. AI 제안을 한 번에 편집안에 적용할 수 있고, 저장된 모든 변경은 과거를 덮지 않는 새 루틴 버전과 새 7일 관찰이 된다.

## 2. 루틴 불변 규칙

- 루틴의 단위는 `routine_version`이다.
- 한 사용자에게 현재 루틴은 0개 또는 1개다.
- 저장된 과거 버전의 item은 수정·삭제하지 않는다.
- 제품·시간대·순서·빈도 중 하나라도 달라진 편집안을 저장하면 새 버전을 만든다.
- 같은 내용으로 저장 요청을 반복하면 멱등 키 기준으로 같은 버전을 반환한다.
- 삭제되지 않은 내 화장품만 새 루틴에 넣을 수 있다. `UNCERTAIN`도 실제 사용 기록을 위해 허용하되 AI 제품 사실은 사용할 수 없다.
- 제품 하나만 있어도 저장 가능하고 빈 루틴은 저장할 수 없다.
- 클렌징 제품도 같은 item 규칙을 사용한다.

## 3. 루틴 item 계약

| 필드 | 필수 | 검증 |
| --- | --- | --- |
| `myProductId` | 필수 | 인증 사용자의 활성 내 화장품 |
| `period` | 필수 | `MORNING` 또는 `EVENING` |
| `position` | 필수 | 시간대 안에서 1부터 빈틈 없이 유일 |
| `frequencyText` | 선택 | 100자 이하 자연어. 미입력 허용 |

같은 내 화장품은 아침과 저녁에 각각 한 번 포함할 수 있지만 같은 시간대에 두 번 넣을 수 없다.

## 4. 만들기·편집 흐름

1. 루틴이 없으면 빈 편집안, 있으면 현재 버전을 복사한 편집안을 연다.
2. 사용자는 아침 또는 저녁에서 `제품 추가`를 누른다.
3. 내 화장품을 선택하거나 목록 아래 `새 화장품 추가`로 등록 흐름을 다녀온다.
4. 새 제품 등록 성공 시 기존 편집안과 스크롤 위치를 보존해 돌아온다.
5. 사용자는 drag 또는 위·아래 이동 버튼으로 순서를 정하고 빈도를 입력한다.
6. 직접 저장하거나 `AI 추천 순서로 배치`를 요청한다.
7. 저장 직전 서버가 item과 최신 현재 버전 충돌을 검증한다.
8. 성공하면 기존 current를 해제하고 새 버전을 current로 만든다.
9. 사용자 시간대의 저장 날짜를 DAY 1로, DAY 7 00:00을 `assessmentDueAt`으로 고정한다.
10. 루틴 저장과 AI 분석 job 생성을 같은 로컬 트랜잭션에서 커밋한 뒤 외부 AI 호출을 시작한다.

사용자에게 `실제 사용 변경`과 `기록 정정`을 구분해 묻지 않는다. 저장하면 항상 새 버전이다.

## 5. AI 추천 순서로 배치

### 5.1 입력

- 현재 편집안 전체
- 각 제품 버전의 공식 사용법·제형·주의 원문과 출처
- 아침/저녁 구분
- 사용자가 포함을 허용한 제품 메모
- 현재 질문에 필요한 AI 기억

과거 루틴의 결과는 순서 설명에 참고할 수 있지만 현재 편집안의 제품을 임의로 추가·삭제하는 근거로 쓰지 않는다.

### 5.2 제안 규칙

1. 입력된 모든 item을 정확히 한 번 유지한다.
2. 제품의 시간대를 바꾸거나 제품을 제거·추가하지 않는다.
3. 공식 사용법에 명시된 선후·시간대 지시를 가장 우선한다.
4. 서로 다른 공식 지시가 충돌하면 자동 제안을 완료하지 않고 충돌 제품과 원문을 보여준 뒤 사용자의 실제 사용 의도를 묻는다.
5. 명시 지시가 없으면 AI가 제형·일반 사용 위치를 근거로 순서를 제안하되 `AI 제안`으로 표시한다.
6. 빈도가 비어 있을 때만 빈도 후보를 제안한다. 사용자가 입력한 빈도를 자동 덮어쓰지 않는다.
7. 각 이동 또는 빈도 제안은 제품 ID, 이전 값, 제안 값, 이유와 출처를 반환한다.
8. 서버는 item 집합 보존, 위치 유일성·연속성, 허용된 시간대와 출처 참조를 검증한다.

`UNCERTAIN` 제품은 이름과 사용자가 정한 위치·빈도만 유지한다. AI는 해당 제품의 공식 사용법을 추정하지 않고 `정보 부족`으로 표시한다.

### 5.3 적용

- 결과 화면은 `달라지는 것`, `그대로인 것`, `확인할 점`을 보여준다.
- `이 순서로 배치`를 눌러야 편집안에 반영한다.
- 반영 후에도 사용자는 자유롭게 고칠 수 있다.
- 적용은 아직 저장이 아니며 취소하면 원래 편집안으로 되돌린다.

## 6. 저장 후 제품별 AI 분석

새 버전 저장 때 `ROUTINE_ANALYSIS` job을 만든다. 결과는 다음 구조를 가진다.

| 단위 | 내용 |
| --- | --- |
| 루틴 전체 | 아침·저녁 조합 요약, 공식 지시 충돌, 정보 부족 |
| 각 item | 이 루틴에서의 위치, 확인된 역할, 함께 볼 사용 조건, 확인할 점 |
| 근거 | 제품 공식 정보, 관련 근거 또는 개인 기록 참조 |

`역할`은 영구 enum으로 저장하지 않고 현재 루틴과 질문을 기준으로 만든 자연어 해석이다. 확인된 제품 사실과 AI 해석을 화면에서 구분한다.

분석 트리거:

- 새 루틴 버전 저장
- 참조한 카탈로그 사실의 버전 변경
- 사용자의 수동 재시도

분석 실패는 루틴 저장과 7일 시작을 취소하지 않는다. 현재 루틴 상단에 실패 상태와 `AI 분석 다시 시도`를 표시한다.

## 7. 조기 변경 연결

DAY 1~6의 현재 루틴에서 편집을 시작하면 F-05의 조기 결과 바텀시트를 먼저 연다.

- 결과를 남겨도 남기지 않아도 같은 편집안으로 이동한다.
- 편집을 취소하면 기존 루틴과 기존 7일 일정은 유지한다.
- 새 버전을 저장한 시점에만 기존 루틴이 current에서 내려가고 새 DAY 1이 시작된다.

## 8. 동시 수정·예외 계약

| 상황 | 결과 |
| --- | --- |
| `expectedCurrentRoutineId`가 최신과 다름 | `409 ROUTINE_VERSION_CONFLICT`, 최신 버전과 기존 편집안 유지 |
| 빈 item 목록 | `422 ROUTINE_EMPTY` |
| 다른 사용자·삭제 제품 | 항목별 `422 INVALID_MY_PRODUCT` |
| 불확실 버전 제품 | 저장은 허용, AI 제안에서 해당 제품 사실을 추정하지 않고 정보 부족 표시 |
| 같은 시간대 중복 제품·위치 | `422 ROUTINE_ITEM_DUPLICATE` 또는 `POSITION_INVALID` |
| AI 순서 작업 실패 | 편집안 유지, 직접 저장·재시도 제공 |
| AI가 item을 누락·추가 | 결과 전체 거절, 원래 편집안 유지 |
| 저장 더블 탭 | 같은 멱등 키로 같은 routine/job 반환 |

## 9. 상태·API·데이터 변화

| 행동 | API | 데이터 변화 |
| --- | --- | --- |
| 현재 루틴 조회 | `GET /me/routines/current` | 없음 |
| 루틴 저장 | `POST /me/routines` | routine version/items, current pointer, notification, job |
| AI 순서 제안 | `POST /routine-order-proposals` | job·analysis, 루틴 미변경 |
| 버전 상세·이력 | `GET /me/routines/{routineId}`, `GET /me/routines/history` | 없음 |

## 10. 수용 시나리오

1. **Given** 현재 v3, **When** 제품 순서 하나를 바꿔 저장하면, **Then** v3는 그대로 남고 v4가 현재 루틴·DAY 1이 된다.
2. **Given** 루틴 편집안, **When** 새 화장품을 등록하고 돌아오면, **Then** 편집안은 보존되고 새 제품을 추가할 수 있다.
3. **Given** AI 제안이 제품 하나를 누락하면, **When** 서버가 검증할 때, **Then** 제안 전체를 거절하고 편집안은 변하지 않는다.
4. **Given** 루틴 저장 뒤 AI 장애, **When** 현재 루틴을 열면, **Then** 루틴과 DAY 1은 유효하고 분석만 재시도할 수 있다.
5. **Given** 두 기기에서 같은 current를 편집, **When** 두 번째 저장이 도착하면, **Then** 충돌을 반환하고 사용자의 편집안을 잃지 않는다.
