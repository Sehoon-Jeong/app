## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 완료 실험과 최종 결과가 하나 이상 있고 새 추천·비교·계획을 만들고 있다. |
| 입력·행동 | 동일 제품의 최근·이전 결과, 당시 루틴 차이, 관련 조합과 반복 관찰을 확인하고 원래 Archive 기록으로 이동한다. |
| 시스템 처리 | 동일 제품의 불편·목적 체감·다음 결정, 이전·재시험 관계, 안정 조합과 반복 관찰을 찾고 실제 기간·횟수·관찰 완성도·다른 변경으로 근거 수준을 계산한다. |
| 사용자 결과 | 자신의 관련 경험과 기록의 한계를 보고 다음 후보와 관찰 계획에 활용한다. |
| 핵심 규칙 | 짧거나 다른 변경이 섞인 결과를 완성도 높은 결과와 같은 무게로 쓰지 않는다. 최신 결과가 있어도 상반된 과거 결과와 당시 조건을 숨기지 않는다. 모든 근거는 원본 실험으로 추적한다. |
| 예외·복구 | 관련 완료 기록이 없으면 개인화 근거를 만들지 않는다. 미완료·취소·미확정 정보는 확정 근거로 쓰지 않는다. 상반된 경험은 하나를 정답으로 고르지 않는다. 과거 추천 스냅샷을 최신 기록으로 바꾸지 않는다. |
| 완료 기준 | 개인 결과와 기록 완성도가 다음 추천·비교에 표시된다. 상반된 사례와 후속 관찰이 함께 보인다. 기록이 없으면 추측하지 않는다. 첫 결과가 두 번째 계획에 실제 반영된다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
