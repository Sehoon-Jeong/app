## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 불편 기록으로 Rescue가 시작됐고 실험이 참조한 안정 루틴과 제품 사용 이력이 있다. |
| 입력·행동 | 비교 기준 안정 루틴, 실험에서 추가·교체한 제품, 계획 밖 변경·중단·재사용과 각 시점을 확인한다. |
| 시스템 처리 | 실험 시작 당시의 안정 루틴·제품 버전과 실제 변경 이벤트를 복원해 Rescue 스냅샷으로 남긴다. 계획 변경과 계획 밖 변경을 구분한다. |
| 사용자 결과 | 마지막으로 안정적이었던 기준 이후 실제로 달라진 제품 범위를 한눈에 본다. |
| 핵심 규칙 | 현재 최신 루틴이 아니라 실험에 고정된 버전을 기준으로 한다. 과거 정보와 시점을 현재 값으로 덮어쓰지 않는다. 이 단계에서는 원인 가능성을 계산하지 않는다. |
| 예외·복구 | 안정 루틴·변경 시점이 부족하면 추측하지 않고 정보 부족으로 표시한다. 동시 변경 제품에 임의 순서를 만들지 않는다. 생활 변화는 제품 목록과 분리한다. |
| 완료 기준 | 과거 Rescue를 다시 열어도 당시 버전이 보인다. 계획된 추가·교체와 계획 밖 변경이 기록과 맞는다. 중단·재사용 시점을 확인한다. 이후 루틴 갱신이 과거 결과를 바꾸지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
