## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 추천 또는 실험 순서가 계산됐고 사용한 루틴·제품·개인 이력의 확인 상태를 추적할 수 있다. |
| 입력·행동 | `근거 자세히 보기`에서 지지 근거, 반대 근거, 개인 경험, 정보 부족과 다른 변수를 확인한다. |
| 시스템 처리 | 구조화된 근거를 다섯 범주로 나누고 재현 가능한 입력 수준을 충분·제한적·부족으로 표시한다. AI는 표현만 담당하며 순위와 강도를 바꾸지 않는다. |
| 사용자 결과 | 추천과 순서를 받아들일지 스스로 판단할 정보를 얻는다. |
| 핵심 규칙 | 근거 강도는 피부 적합 확률이 아니다. 동일 제품의 불편 기록과 상반된 사례를 숨기지 않는다. 진단·치료·적합도 보장 표현을 사용하지 않는다. |
| 예외·복구 | 핵심 정보가 부족하면 확정 설명보다 부족한 정보와 보완 행동을 먼저 보여준다. 한 번의 개인 결과를 반복 패턴으로 표현하지 않는다. 동시 변경·생활 변화가 있으면 근거 강도를 낮추고 이유를 표시한다. |
| 완료 기준 | 적용되는 지지·반대·부족 정보를 구분한다. 근거 강도를 확률로 오해시키지 않는다. AI 설명이 순위나 강도를 바꾸지 않는다. 정보 부족 후보에 확정 문구가 나오지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
