## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 로그인하지 않은 사용자가 처음 가입하거나 기존 계정으로 돌아온다. |
| 입력·행동 | 이메일과 비밀번호로 가입 또는 로그인하고, 필요하면 로그아웃한다. |
| 시스템 처리 | 이메일을 정규화하고 비밀번호는 단방향 해시로 저장한다. 서버는 30일짜리 단일 access JWT를 발급하고, 프론트엔드는 `sessionStorage`에 저장해 Bearer 헤더로 전송한다. 로그인 후 현재 안정 루틴과 열린 실험을 조회한다. |
| 사용자 결과 | 신규 사용자는 안정 루틴 등록으로, 기존 사용자는 진행 중인 실험 또는 홈으로 이동한다. 같은 브라우저 세션에서는 새로고침해도 인증 상태를 유지한다. |
| 핵심 규칙 | refresh token·인증 cookie·서버 인증 세션은 사용하지 않는다. 데이터 소유자는 JWT의 인증 주체로 결정하고 프론트엔드가 보낸 사용자 ID를 신뢰하지 않는다. 비밀번호와 JWT를 저장하거나 로그에 노출하지 않는다. |
| 예외·복구 | 잘못된 형식과 자격 증명은 수정 가능한 오류로 안내한다. JWT가 만료됐거나 브라우저 세션이 끝났으면 기록을 유지한 채 재로그인을 요청한다. 소셜 로그인·비밀번호 재설정은 MVP 밖이다. |
| 완료 기준 | 가입 후 안정 루틴 등록에 도달한다. 기존 사용자의 루틴과 열린 실험이 복원된다. 로그아웃 시 `sessionStorage`의 인증 정보가 삭제되고 토큰 없는 개인 API 요청이 거부된다. 다른 사용자의 식별자로 기록을 조회할 수 없다. |

## 연결 원칙
