## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 같은 제품·성분·기능 또는 제품군과 관련된 완료 실험이 두 개 이상이고 확인된 제품 정보와 연결된다. |
| 입력·행동 | 개인 패턴에서 같은 방향 결과 횟수·전체 관련 실험·반대 사례와 루틴 차이를 보고 각 원본 실험을 연다. |
| 시스템 처리 | 같은 방향 결과가 두 번 이상인 항목만 패턴 후보로 집계한다. 분자·분모·반대 사례·원본 링크를 계산하고 추천에 사용한 값은 당시 근거로 저장한다. |
| 사용자 결과 | 반복된 경험을 과장 없이 다음 실험의 관찰 포인트로 활용한다. |
| 핵심 규칙 | 패턴은 원본 실험의 집계이며 별도 사실로 복제하지 않는다. 반복과 원인 확인을 구분한다. 반대 사례를 숨기지 않는다. 개인 패턴을 집단 코호트나 의학적 상관으로 표현하지 않는다. |
| 예외·복구 | 한 번의 결과·미완료·취소·AI 추측 성분은 제외한다. 제품 버전 차이로 비교할 수 없으면 제외 이유를 정보 부족으로 표시한다. |
| 완료 기준 | 한 사례는 패턴으로 보이지 않는다. 두 사례 이상이면 분자·분모·반대 사례가 함께 나온다. 모든 원본으로 이동한다. 미확정 정보가 제외되고 원인·안전성을 단정하지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
