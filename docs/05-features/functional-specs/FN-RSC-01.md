## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 진행·보류 중인 실험 또는 완료 실험의 후속 관찰에서 사용자가 불편함을 선택했다. |
| 입력·행동 | 불편 유형·정도·부위·처음 인지한 시점, 필요한 경우 평소와 달랐던 일과 악화·도움 필요 여부를 기록한다. 제품 사용 중단 여부도 선택한다. |
| 시스템 처리 | 불편 기록과 Rescue를 중복 없이 만들고, 심함·악화·도움 필요 조건이면 일반 제품 행동 제안을 중단하고 고정 안전 안내를 먼저 표시한다. 진행 중 중단 선택은 보류 이력으로 남기며 완료 실험의 상태·결과는 바꾸지 않는다. |
| 사용자 결과 | 짧은 기록을 남기고 안전 안내와 최근 변경 확인으로 이어간다. |
| 핵심 규칙 | 불편 정도는 필수다. 생활 변화는 불편 시에만 선택적으로 묻고 화장품 외 변수로서 근거 강도를 낮추는 데만 사용한다. 안전 우선 조건에서는 사용자가 안내를 확인한 뒤 변경 사실만 볼 수 있다. |
| 예외·복구 | 생활 변화를 모르거나 답하지 않아도 불편 기록은 저장한다. 불편 유형은 질환 분류가 아니다. 심하거나 지속되는 불편에는 제품 사용 중단과 의료 전문가 확인을 안내한다. |
| 완료 기준 | 안전 우선 조건에서 일반 제품 행동 제안이 나오지 않는다. 완료 후 불편도 원래 결과를 수정하지 않고 연결된다. 실제 관찰·입력 시각을 구분하고 진행 중 중단만 보류 이력에 남는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
