## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 완료 또는 취소 실험이 하나 이상 있고 당시 루틴·제품·실험 이력이 보존됐다. 현재 보류 중인 열린 실험은 제외한다. |
| 입력·행동 | 최근 기록부터 목록을 보고 결과·제품 종류로 필터링한 뒤 상세에서 당시 루틴·비교·관찰·Rescue·결과·재시험을 확인한다. |
| 시스템 처리 | 기존 실험·관찰·Rescue·결과·루틴 버전을 조회해 Archive를 구성한다. 별도 결과 원본을 만들지 않는다. |
| 사용자 결과 | 완료한 실험을 찾고 당시의 전체 판단 맥락을 다시 확인한다. |
| 핵심 규칙 | 기본 정렬은 최근 완료순이다. 현재 정보가 아니라 당시 고정 버전을 보여준다. 소유자만 조회할 수 있고 Archive에서 과거 결과·루틴을 수정하지 않는다. |
| 예외·복구 | 결과 없는 취소는 취소 이유와 결과 없음을 구분한다. 일부 정보가 부족해도 가능한 이력을 보여주고 추측하지 않는다. 일반 제거는 원본 물리 삭제가 아니며 계정 삭제는 별도 기능이다. |
| 완료 기준 | 목록에서 제품·목적·실제 기간·결과·관찰 완료율을 본다. 필터와 정렬이 동작한다. 상세 이력이 원본과 일치한다. 다른 사용자의 Archive에 접근할 수 없다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
