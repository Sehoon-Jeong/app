## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 해금 조건·보상 자산이 정의됐고 사용자에게 완료 퀘스트 또는 실험이 있다. |
| 입력·행동 | 잠긴 보상의 조건을 보고 관찰·실험을 완료한 뒤 새 보상과 획득 근거를 확인한다. |
| 시스템 처리 | 명시된 조건과 버전으로 해금 여부를 계산하고 일회성 배지는 사용자·배지 조합당 한 번만 만든다. |
| 사용자 결과 | 어떤 실험 행동으로 배지와 장식을 얻었는지 이해한다. |
| 핵심 규칙 | 첫 연구 완료·필수 관찰 100%·Rescue 후 완료처럼 정의된 조건만 사용한다. 결과 방향을 차별하지 않는다. AI가 보상을 결정하지 않는다. |
| 예외·복구 | 연속 접속·로그인·알림 클릭·체류 시간은 조건이 아니다. 미확정 보상과 조건을 구현자가 임의로 추가하지 않는다. |
| 완료 기준 | 조건을 충족할 때만 해금된다. 재처리에도 중복되지 않는다. 조건과 획득 근거를 확인한다. 출석만 반복해도 보상이 바뀌지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
