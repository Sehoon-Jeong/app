## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | Rescue가 안정 루틴 이후 변경점, 불편 기록, 사용 시점과 부족 정보를 구조화했다. |
| 입력·행동 | 안전 우선 안내와 제품별 우선 확인·잠시 보류·유지 후보·판단 어려움, 근거·반대 근거·부족 정보와 다음 행동을 확인한다. |
| 시스템 처리 | 서버의 버전이 있는 일반 규칙으로 제품별 단일 분류를 계산한다. AI는 계산된 근거와 행동을 설명하며 검증 실패 시 고정 템플릿을 사용한다. |
| 사용자 결과 | 루틴 전체를 포기하지 않고 먼저 확인할 범위와 중단·유지·추가 관찰·재시험 행동을 정한다. |
| 핵심 규칙 | 분류를 인과 확률로 표현하지 않는다. AI가 제품 ID·분류·행동을 바꾸지 않는다. 유지 후보는 안전 보장이 아니며 안전 우선 조건에서는 중단·전문가 안내가 먼저다. |
| 예외·복구 | 특정 제품·성분을 원인·범인·안전 제품으로 단정하지 않는다. 안정 루틴 부재·동시 변경·생활 변화·누락 정보는 판단 어려움이나 낮은 근거로 반영한다. 보류는 실패 판정이 아니다. |
| 완료 기준 | 같은 입력·정책에서 분류가 재현된다. 변경 제품과 유지 제품이 규칙대로 나뉜다. 다른 변수가 근거 강도에 반영된다. AI 실패에도 같은 행동이 보인다. 안전 안내가 우선한다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
