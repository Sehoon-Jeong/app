## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | Rescue가 안정 루틴 이후 변경점, 불편 기록, 사용 시점과 부족 정보를 구조화했다. |
| 입력·행동 | 안전 안내와 제품별 최근 추가·교체·함께 변경·변경 기록 없음·정보 부족, 근거·반대 근거와 확인 순서를 본다. |
| 시스템 처리 | 서버의 버전이 있는 일반 규칙으로 제품별 단일 사실 분류를 계산한다. AI는 계산된 사실과 부족 정보를 설명하며 검증 실패 시 고정 템플릿을 사용한다. |
| 사용자 결과 | 제품을 원인이나 안전 제품으로 오해하지 않고 먼저 확인할 변경 범위를 이해한다. |
| 핵심 규칙 | 분류를 인과 확률·안전성·계속 사용 권고로 표현하지 않는다. AI가 제품 ID·사실 분류를 바꾸지 않는다. 안전 우선 조건에서는 일반 행동 제안을 중단하고 안내 확인 뒤 변경 이력만 제공한다. |
| 예외·복구 | 안정 루틴 부재·동시 변경·생활 변화·누락 정보는 정보 부족이나 낮은 근거로 반영한다. `변경 기록 없음`은 원인 배제나 사용 유지가 아니다. |
| 완료 기준 | 같은 입력·정책에서 사실 분류가 재현된다. 다른 변수가 근거 강도에 반영된다. AI 실패에도 동일한 사실이 보인다. 안전 우선 조건에서 일반 제품 행동 제안이 나오지 않는다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
