## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 로그인했고 안정 루틴에 넣을 제품 또는 실험 후보를 찾고 있다. |
| 입력·행동 | 제품명이나 브랜드명 일부를 입력하고 결과에서 브랜드·제품명·종류·확인 상태를 본 뒤 하나를 선택한다. |
| 시스템 처리 | 운영 확인된 활성 카탈로그 제품을 정규화된 제품명·브랜드명으로 검색하고 최신 확인 버전을 반환한다. 루틴 입력과 후보 저장의 유입 맥락은 구분한다. |
| 사용자 결과 | 실제 제품을 찾아 안정 루틴 또는 실험 후보 입력으로 돌아간다. |
| 핵심 규칙 | 운영 확인되지 않은 개인 초안은 다른 사용자의 검색에 나오지 않는다. 유사 제품을 자동 선택하지 않고 사용자가 제품 버전을 확인한다. 검색 순서는 광고나 구매 전환의 영향을 받지 않는다. |
| 예외·복구 | 결과가 없으면 검색어를 바꾸거나 P1 직접 등록으로 이동한다. 직접 등록을 사용할 수 없는 P0 시연 범위에서는 지원 제품이 아님을 명확히 알린다. 네트워크 실패에도 검색어와 이전 화면 입력을 유지한다. |
| 완료 기준 | 제품명·브랜드 부분 검색이 동작한다. 비활성·개인 제품이 노출되지 않는다. 선택한 제품이 원래 루틴 또는 후보 흐름으로 돌아간다. 결과 없음과 재시도 행동이 보인다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
