# F-01 계정·온보딩·AI 기억

## 1. 사용자가 얻는 결과

사용자는 계정별로 기록을 분리하고, 최소한의 자연어 맥락을 AI에 알려주며, AI가 이후 대화에서 기억할 내용을 직접 확인·수정·삭제한다. 온보딩을 건너뛰어도 핵심 기능을 사용할 수 있다.

## 2. 범위

포함:

- 이메일 가입·로그인
- 선택형 AI 온보딩 대화
- AI 기억 확인·추가·수정·삭제
- 시간대 변경
- 계정과 개인 데이터 영구 삭제

제외:

- 소셜 로그인, 비밀번호 재설정, 다중 기기 세션 관리
- 피부 유형·질환을 확정하는 정형 프로필
- 대화 내용을 사용자의 확인 없이 기억으로 자동 확정하는 동작

## 3. 진입·종료 조건

| 흐름 | 진입 조건 | 성공 종료 | 중단해도 남는 것 |
| --- | --- | --- | --- |
| 가입 | 로그인하지 않은 사용자가 이메일·비밀번호 제출 | 세션 발급, 온보딩 미완료 상태 | 없음 |
| 로그인 | 등록된 이메일·비밀번호 제출 | 세션 발급, 홈 또는 미완료 온보딩으로 이동 | 없음 |
| 온보딩 | 가입 직후 또는 내 정보에서 다시 열기 | 확인한 기억 저장 후 홈 | 이미 확인한 기억만 저장 |
| 기억 관리 | 내 정보에서 `AI가 기억하는 내용` 선택 | 항목별 변경 즉시 반영 | 성공한 변경만 저장 |
| 계정 삭제 | 로그인 사용자가 `DELETE` 확인 | 삭제 작업 생성, 새 쓰기 잠금 | 삭제 job 상태 |

## 4. 입력과 데이터 권한

| 입력 | 필수 | 규칙 | 저장 위치 |
| --- | --- | --- | --- |
| 이메일 | 가입·로그인 필수 | 이메일 형식, 계정 간 유일 | `app_user.email` |
| 비밀번호 | 가입·로그인 필수 | 8자 이상, 원문 저장·로그 금지 | 해시만 `password_hash` |
| 시간대 | 가입 시 기본값 | IANA timezone, 기본 `Asia/Seoul` | `app_user.timezone` |
| 온보딩 답 | 선택 | 항목당 1,000자 이하 자연어 | 확인 후 `ai_memory` |
| 기억 문장 | 사용자가 저장할 때 필수 | 빈 문자열 금지, 1,000자 이하 | `ai_memory` |

AI에 전달하는 온보딩 범위는 다음 네 질문의 현재 답뿐이다.

1. 요즘 피부에서 신경 쓰이는 점
2. 선호하는 사용감
3. 피하고 싶은 조건
4. 제품을 고를 때 알고 싶은 점

루틴·사용 결과는 AI 기억으로 복제하지 않는다. 구조화된 원본 이력을 요청별로 참조한다.

## 5. 온보딩 정상 흐름

1. 가입 성공 후 첫 질문을 보여준다.
2. 한 번에 한 질문을 보여주고 이전 메시지는 대화에 유지한다.
3. 사용자는 자연어로 답하거나 `잘 모르겠어요`, `건너뛰기`를 누른다.
4. 답을 받으면 AI가 기억 후보 문장 하나로 요약한다.
5. 화면은 원문과 요약을 함께 보여주고 `이대로 기억`, `수정`, `기억하지 않기`를 제공한다.
6. `이대로 기억` 또는 수정 확정 시에만 `ai_memory`를 만든다. 출처는 `ONBOARDING`이다.
7. 네 질문을 모두 답하거나 건너뛰면 `onboardingComplete=true`로 저장하고 홈으로 이동한다.

AI 요약은 새로운 피부 상태·원인·제품 선호를 추가할 수 없다. 원문보다 강한 표현이 포함되면 서버는 저장하지 않고 원문 저장 또는 직접 수정을 제공한다.

`잘 모르겠어요`는 개인 성향으로 기억하지 않는다. AI는 원래 질문보다 답하기 쉬운 관찰 질문이 있을 때만 한 번 바꿔 물을 수 있다. 다시 모르겠다고 하거나 건너뛰면 다음 질문으로 이동하며 기억을 만들지 않는다.

## 6. AI 기억 관리

- 목록은 삭제되지 않은 기억을 최신 수정순으로 보여준다.
- 항목마다 현재 문장, 출처, 최종 수정 시각을 표시한다.
- 사용자가 직접 추가하거나 수정한 항목의 출처는 `USER_EDIT`이다.
- 제품 의견·추천·Rescue 대화에서 `기억해줘`를 명시하고 확인한 항목만 `CONVERSATION`으로 저장한다.
- 삭제는 soft delete 후 모든 새 AI 요청에서 즉시 제외한다.
- 수정은 기존 항목을 갱신하되 감사 로그가 필요하면 구현 계층에서 별도 이력을 둔다. 사용자에게는 현재 문장만 보여준다.
- 동일 문장을 중복 저장하려 하면 기존 항목을 보여주고 새 항목을 만들지 않는다.

## 7. 실패·예외 계약

| 상황 | 사용자에게 보이는 결과 | 저장 규칙 |
| --- | --- | --- |
| AI 요약 실패 | 원문 그대로 기억하거나 직접 고치기 | 확인 전에는 저장하지 않음 |
| 네 질문 모두 건너뜀 | 개인화가 적다는 짧은 안내 후 홈 | `onboardingComplete=true`, 기억 0개 허용 |
| `잘 모르겠어요` 뒤에도 답하기 어려움 | 정보가 없어도 이용할 수 있다는 안내 후 다음 질문 | 해당 질문의 기억을 만들지 않음 |
| 가입 이메일 중복 | 이메일 입력 가까이에 중복 오류 | 계정 생성 안 함 |
| 로그인 실패 | 이메일·비밀번호가 맞지 않는다는 공통 오류 | 존재 여부 노출 금지 |
| 다른 사용자 기억 ID 접근 | 없는 항목과 같은 응답 | 조회·수정·삭제 없음 |
| 삭제 작업 중 추가 쓰기 | 계정 삭제 진행 중 안내 | 새 개인 데이터 쓰기 거절 |

## 8. 상태·API·데이터 변화

| 사용자 행동 | API | 성공 상태 변화 |
| --- | --- | --- |
| 가입 | `POST /auth/sign-up` | `app_user` 생성, 세션 발급 |
| 로그인 | `POST /auth/login` | 세션 발급 |
| 온보딩·시간대 확정 | `PATCH /me` | profile 필드 갱신 |
| 기억 목록·추가 | `GET/POST /me/ai-memories` | `ai_memory` 조회·생성 |
| 기억 수정·삭제 | `PATCH/DELETE /me/ai-memories/{memoryId}` | 현재 문장 갱신 또는 삭제 처리 |
| 계정 삭제 | `DELETE /me` | 쓰기 잠금, 삭제 job 생성 |

소유권 판단은 항상 인증 사용자 ID로 한다. 클라이언트가 보낸 `userId`는 받지 않는다.

## 9. 수용 시나리오

1. **Given** 새 이메일 계정, **When** 가입하고 네 질문을 모두 건너뛰면, **Then** 기억 0개 상태로 홈에 도달한다.
2. **Given** 온보딩 답변, **When** AI 요약을 수정해 확정하면, **Then** 수정한 문장만 다음 AI 요청에 포함된다.
3. **Given** 저장된 기억, **When** 삭제하면, **Then** 목록에서 사라지고 이후 제품 의견 요청의 입력 스냅샷에도 포함되지 않는다.
4. **Given** 사용자 A의 기억 ID, **When** 사용자 B가 조회·수정·삭제하면, **Then** 모두 찾을 수 없음으로 처리되고 A의 데이터가 변하지 않는다.
5. **Given** AI 요약 장애, **When** 사용자가 원문 저장을 선택하면, **Then** 온보딩을 끝낼 수 있다.
6. **Given** 사용자가 온보딩 질문에 `잘 모르겠어요`라고 답함, **When** 쉬운 관찰 질문에도 답하지 않으면, **Then** 피부 상태를 추정하거나 기억으로 저장하지 않고 다음 질문으로 이동한다.

연결 요구사항: ACC-01, ACC-02, ONB-01, ONB-02, MEM-01, MEM-02
