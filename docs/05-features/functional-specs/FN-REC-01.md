## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 확인한 안정 루틴이 있다. 사용 목적과 추가·교체 의도를 정했고, 교체라면 대상 제품을 골랐다. |
| 입력·행동 | 피부 고민, 사용 목적, 추가·교체 의도와 선택 조건을 입력한다. 모르는 항목은 `잘 모르겠어요`로 남길 수 있다. |
| 시스템 처리 | 서버가 목적 관련성, 목적과 무관한 중복·변수 수, 정보 확인 수준, 관련 개인 경험과 기록 완성도를 순서대로 계산해 실제 제품 후보와 우선순위를 정한다. AI는 목적 문장을 구조화하고 계산된 순위와 근거를 설명한다. |
| 사용자 결과 | 실제 제품 후보를 최대 3개까지 하나의 다음 실험 우선순위로 보고 목적 관련성, 현재 루틴과의 관계, 주요 중복과 관찰 이유를 확인한다. |
| 핵심 규칙 | 추천은 구매 답안이나 피부 적합성 보장이 아니라 다음 실험 후보다. 운영 확인된 제품만 사용하며 광고가 자격·순서에 영향을 주지 않는다. 관련 개인 기록은 기간·횟수·다른 변경과 함께 반영하고 불편 이력을 숨기지 않는다. 후보가 적으면 수를 억지로 채우지 않는다. |
| 예외·복구 | 안정 루틴·교체 대상·적격 후보가 없으면 이유와 필요한 다음 행동을 안내한다. 정보가 부족해도 추측하지 않고 부족 상태를 표시한다. 진단·치료 조언·적합성 단정을 하지 않는다. |
| 완료 기준 | 같은 입력·정책에서는 같은 순서가 나온다. 루틴이 다르면 중복·변수와 이유가 달라진다. 개인 실험의 기록 완성도가 다음 결과에 반영된다. AI 실패·미사용에도 같은 후보·순위와 고정 설명을 제공한다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
