## 기능 동작

| 항목 | 명세 |
| --- | --- |
| 시작 조건 | 확인한 안정 루틴이 있다. 사용 목적과 추가·교체 의도를 정했고, 교체라면 대상 제품을 골랐다. |
| 입력·행동 | 피부 고민, 사용 목적, 추가·교체 의도와 선택 조건을 입력한다. 모르는 항목은 `잘 모르겠어요`로 남길 수 있다. |
| 시스템 처리 | 서버가 카탈로그에서 추천 자격이 있는 실제 제품을 정하고 목적 관련성·개인 이력·루틴 변화·정보 확인 수준을 계산한다. AI는 허용된 제품 안에서 순위와 설명을 제안하며 서버 검증 실패 시 규칙 기반 순서를 사용한다. |
| 사용자 결과 | 실제 제품 후보를 최대 3개까지 보고 목적 관련성, 현재 루틴과의 관계, 주요 중복과 관찰 이유를 확인한다. |
| 핵심 규칙 | 추천은 구매 답안이나 피부 적합성 보장이 아니라 다음 실험 후보다. 운영 확인된 제품만 사용한다. 관련 개인 기록은 일반 정보보다 먼저 반영하되 불편 이력을 숨기지 않는다. 후보가 적으면 수를 억지로 채우지 않는다. |
| 예외·복구 | 안정 루틴·교체 대상·적격 후보가 없으면 이유와 필요한 다음 행동을 안내한다. 정보가 부족해도 추측하지 않고 부족 상태를 표시한다. 진단·치료 조언·적합성 단정을 하지 않는다. |
| 완료 기준 | 루틴이 다르면 추천 이유도 달라진다. 모든 카드에 실제 제품과 관찰 이유가 보인다. 개인 실험이 다음 추천에 반영된다. AI 실패에도 검증된 규칙 기반 후보를 제공한다. |

## 연결 원칙

- 사용자 흐름과 완료 조건의 상세 원본은 위 GitHub Story다.
- 요청·응답은 [OpenAPI](../../api/README.md), 저장 구조는 [데이터 사전](../../06-data-model/data-dictionary.md)에서 확인한다.
- 제품 의미가 달라지면 이 파일과 Story를 같은 변경에서 함께 수정한다.
