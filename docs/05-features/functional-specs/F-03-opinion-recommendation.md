# F-03 제품 의견·추천

## A. “이거 사볼까?”

1. 사용자가 외부에서 본 제품을 검색한다.
2. 없으면 카탈로그 검수 요청을 남기고 의견은 만들지 않는다.
3. 필요하면 AI가 “이 제품으로 무엇을 바꾸고 싶은지” 한두 가지를 묻는다.
4. 분석은 현재 목적, 현재·안정 루틴, 내 화장품, 메모, 과거 결과, 제품 공식 정보와 관련 근거를 사용한다.
5. 서버는 AI가 인용한 제품 버전과 출처가 실제로 존재하고 사용자 기록 참조가 본인 것인지 검증한다.
6. 결과는 네 결론 중 하나, 살 이유, 망설일 이유, 정보 부족, 내 루틴 변화와 출처를 보여준다.
7. 사용자는 같은 화면의 채팅에서 근거·대안·사용법을 이어 묻는다.
8. `샀어요`, `찜`, `비슷한 제품`으로 다음 행동을 선택한다.

## B. “다음 제품 추천”

1. 사용자가 원하는 변화와 조건을 자연어로 말한다.
2. AI는 후보를 크게 바꾸는 정보가 비어 있을 때만 추가 질문한다. 답은 AI 기억에 저장할 수 있다.
3. AI가 OpenAI 웹 검색으로 허용 출처와 실제 카탈로그를 조사한다.
4. 서버는 국내 판매 버전, 중복 보유, 제외 조건, 출처와 필드 신선도를 검증한다.
5. 통과한 후보만 최대 5개 반환한다. 0개도 정상 결과다.
6. 후보마다 추천 이유, 반대 근거, 정보 부족, 루틴에서 달라지는 점을 보여준다.

## 결론 코드

| 코드 | 사용자 문구 | 의미 |
| --- | --- | --- |
| CONSIDER | 지금 고려할 이유가 커요 | 현재 목적과 연결되고 강한 중복·제외 사유가 확인되지 않음 |
| OVERLAP | 비슷한 제품이 이미 있어요 | 현재 루틴 또는 미사용 보유품과 핵심 역할이 크게 겹침 |
| LOW_RELEVANCE | 지금 찾는 변화와는 거리가 있어요 | 확인된 제품 정보가 현재 목적을 직접 뒷받침하지 않음 |
| INSUFFICIENT | 지금은 판단할 정보가 부족해요 | 제품 버전, 공식 정보 또는 개인 맥락이 부족함 |

이 코드는 피부 적합성과 구매 성공 판정이 아니다.

## 예외와 완료 조건

- AI 검색 실패: 재시도와 기존 카탈로그 사실만 보는 경로를 제공한다.
- 출처가 약함: 결과를 만들더라도 해당 주장을 `정보 부족`으로 낮춘다.
- 보유 제품은 비슷한 제품 목록에서 `보유 중`으로 비활성화한다.
- 가격·판매처는 참고로만 표시하고 결론·순서 입력에서 제외한다.
- 결과는 사용한 루틴 버전, 카탈로그 버전, 개인 기록 참조, 검색 시각과 모델 정보를 남긴다.
