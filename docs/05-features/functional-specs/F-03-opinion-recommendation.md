# F-03 제품 의견·추천

## 1. 사용자가 얻는 결과

P0에서 사용자는 외부에서 본 제품 하나를 자신의 현재·안정 루틴과 과거 결과로 다시 본다. 이 기능은 구매 성공이나 피부 적합성을 판정하지 않는다. 이전 사용 경험이 다음 선택의 근거로 재사용되는지를 검증한다.

## 2. 우선순위 범위

| 우선순위 | 결과 | 요구사항 |
| --- | --- | --- |
| P0 | 한 제품의 최소 개인화 의견과 `샀어요` 등록 | OPN-01~03, OPN-06 |
| P1 | 같은 제품과 근거를 유지하는 후속 채팅 | OPN-04 |
| P2 | 처음부터 제품 추천·유사 제품·찜 | REC-01~04, OPN-05 |

## 3. P0 계약 · 이거 사볼까?

### 3.1 입력 snapshot

분석을 시작할 때 아래 값을 복사해 고정한다.

| 입력 | 규칙 |
| --- | --- |
| 대상 제품 | 확인 제품 또는 이름 직접 입력 제품 하나 |
| 사용자의 질문·목적 | 원문 그대로 저장. 명확하지 않아도 진행 가능 |
| 현재 루틴 | 제품·아침/저녁·순서·빈도 |
| 마지막 안정 루틴 | 있으면 별도 참조 |
| 과거 결과·Rescue | 대상 또는 비교 가능한 기록만 |
| 큐레이션 제품 사실 | `VERIFIED`이고 P0 DB에 있을 때만 |

범용 AI 기억, 제품 메모와 실시간 웹 검색은 P0 입력이 아니다. 피부 고민을 고정 enum으로 영구 저장하지 않고 현재 질문의 문장 맥락으로 해석한다.

### 3.2 처리

1. 서버가 대상 제품과 모든 개인 기록의 소유권을 확인한다.
2. 서버가 현재·안정 루틴 차이와 관련 과거 결과를 계산한다.
3. AI가 질문의 목적을 자연어로 구조화한다. 결론이 크게 달라질 때만 질문을 최대 2개 한다.
4. 모든 질문은 `잘 모르겠어요`로 넘어갈 수 있다.
5. 서버가 확인된 사실, 개인 기록, 정보 부족을 구분해 결과 envelope를 검증한다.
6. AI는 검증된 비교를 쉬운 말로 설명하되 적합·안전·효능을 판정하지 않는다.

### 3.3 결과

| 영역 | 규칙 |
| --- | --- |
| 한 줄 의견 | `지금 비교할 이유가 있음`, `가진 제품과 많이 겹침`, `목적과 관련이 낮음`, `정보가 부족함` 중 서버 결론 |
| 살펴볼 이유 | 목적·루틴·과거 결과 중 실제 근거 참조 |
| 망설일 이유 | 중복, 반대 기록 또는 확인되지 않은 정보 |
| 아직 모르는 것 | 비어 있으면 확인한 범위를 명시. 모르는 것을 없다고 쓰지 않음 |
| 개인 기록 | 날짜·루틴 버전·루틴 전체 결과임을 표시 |
| 면책 | 구매·적합·안전·효능 보장이 아님 |

P0는 근거가 없는 수치 점수나 적합 확률을 표시하지 않는다. `VERIFIED` 제품 사실이 없으면 개인 기록과 루틴 비교만 설명하고 제품 자체 주장은 `정보 부족`으로 남긴다.

### 3.4 후속 행동

- `샀어요`는 제품을 내 화장품에 추가할 뿐 루틴을 자동 변경하지 않는다.
- 이미 가진 제품이면 기존 항목을 보여주고 중복 등록하지 않는다.
- 제품을 실제 루틴에 넣고 결과를 남기면 이후 같은 제품 의견에서 해당 경험을 근거로 다시 사용한다.

### 3.5 P0 실패·API·수용

| 상황 | 결과 |
| --- | --- |
| AI 실패 | 질문·제품·입력 snapshot 보존, 고정 비교 사실 표시 또는 재시도 |
| 분석 중 루틴 변경 | 당시 snapshot 결과임을 표시, 최신 기준 새 요청 제공 |
| 제품 사실 미확인 | 의견을 막지 않고 정보 부족 표시 |
| 다른 사용자 기록 참조 | 결과 전체 거절 |

API는 `POST /product-opinions`, `GET /product-opinions/{opinionId}`, `POST /me/products`를 사용한다.

1. **Given** 같은 역할의 현재 제품, **When** 의견을 요청하면, **Then** 해당 루틴 항목을 근거로 겹침을 설명한다.
2. **Given** 확인 제품 사실이 없음, **When** 의견을 요청하면, **Then** 성분·효능을 만들지 않고 정보 부족을 표시한다.
3. **Given** 과거 결과가 있음, **When** 관련 제품 의견을 요청하면, **Then** 그 기록이 루틴 전체 관찰임을 밝히고 근거로 연결한다.

## 4. P1 계약 · 제품 후속 채팅과 외부 근거

- 후속 질문은 같은 `conversationId`와 최초 snapshot을 사용한다.
- 사용자가 최신 루틴 기준을 요청하면 새 `analysis_request`를 만들고 이전 결과를 덮지 않는다.
- 제품 주장은 허용 출처의 `evidence_snapshot`과 연결한다.
- 완제품 공식 정보, 완제품 사람 대상 연구, 원료 연구와 개인 경험의 강도를 구분한다.
- 원료 연구 하나를 완제품 효과로 바꾸거나 리뷰·인기·가격을 결론에 사용하지 않는다.

P1은 후속 메시지마다 새 실행 이력을 남기되 최초 검증 결론을 몰래 바꾸지 않는다.

## 5. P2 계약 · 제품 추천·유사 제품·찜

### 5.1 추천 흐름

1. 사용자가 원하는 변화를 자연어로 말한다.
2. AI는 후보 포함·제외를 바꾸는 정보만 최대 3번 묻는다.
3. 서버는 국내 `VERIFIED + ACTIVE` 실제 제품, 명시한 제외 조건과 출처를 검증한다.
4. 서버가 목적 직접성, 현재 루틴의 새 차이, 근거 완전성, 개인 비교 가능성과 정보 부족으로 순서를 정한다.
5. 최대 5개를 반환하며 통과 제품이 없으면 0개도 정상이다.

순위는 잘 맞을 확률이 아니라 현재 질문을 설명하고 다음에 시험하기 쉬운 순서다. 가격·판매량·광고비·제휴 수수료는 순위에 쓰지 않는다.

### 5.2 유사 제품과 찜

- 유사 제품은 별도 목록으로 열고 제품 채팅으로 자동 이동하지 않는다.
- 찜은 구매·보유·루틴 상태와 분리한다.
- `샀어요` 이후 내 화장품으로 전환해도 과거 찜 이력을 보존한다.

연결 요구사항: OPN-01~06, REC-01~04
