# Rescue와 Beauty Archive

## 한눈에 보기

불편함이 생기면 마지막 안정 루틴 이후 실제로 달라진 제품을 복원한다. 서비스는 기록된 사실로 확인 범위를 나누고 AI는 근거·반대 근거·부족한 정보를 설명한다. 결과를 완료하면 실험은 Archive에 남고, 사용자가 원할 때만 새 안정 루틴으로 승격된다.

연결 요구사항: `FR-RSC-001~005`, `FR-ARC-001~006`, `FR-EXP-005`, `FR-REC-005`

## 1. Rescue 시작

연결 이슈: [#22 피부 불편과 평소와 달랐던 변화 기록](https://github.com/sksksksksksss/service/issues/22)

다음 중 하나가 발생하면 Rescue를 시작한다.

- 관찰에서 `불편함`을 선택
- 사용자가 예정 밖 `피부가 불편해졌어요` 행동을 선택
- 사용자가 제품 사용을 불편함 때문에 중단

Rescue를 시작해도 실험 결과를 자동 확정하지 않는다. 현재 실험은 사용자의 선택에 따라 `PAUSED`가 되고, 기록된 시점과 이유를 남긴다.

### 먼저 확인할 안전 질문

1. 불편 정도가 심한가
2. 사용자가 전문가 도움이 필요하다고 느끼는가
3. 넓게 퍼지거나 빠르게 심해지고 있다고 사용자가 선택했는가

하나라도 해당하면 선택적 제품 분류보다 다음 안내를 먼저 보여준다.

> 새로 사용한 제품을 포함한 선택적 화장품 사용을 중단하고, 증상이 심하거나 계속되면 의료 전문가에게 확인하세요. SkinCause는 원인이나 질환을 판단하지 않습니다.

이 안내는 응급 진단이 아니며 사용자가 도움을 구하도록 하는 안전 경계다.

## 2. 변경점 복원

연결 이슈: [#23 마지막 안정 루틴 이후 변경 제품 확인](https://github.com/sksksksksksss/service/issues/23)

서버는 다음 데이터를 시간순으로 결합한다.

1. 현재 실험이 참조한 안정 루틴 버전
2. 실험의 추가·교체 계획과 실제 시작 시각
3. 사용 시간대·순서 변경 이력
4. 제품 중단·재사용 기록
5. 사용자가 추가로 입력한 다른 화장품 변경
6. 불편함을 처음 알아차린 시점
7. 선택적으로 기록한 평소와 다른 생활 변화

비교 결과에는 `안정 루틴에 있던 제품`, `실험으로 바뀐 제품`, `기록 밖에서 함께 바뀐 제품`, `시점이 불명확한 변화`를 구분해 표시한다.

사용자에게 이미 아는 정보를 다시 묻지 않는다. 다음 분류에 영향을 주지만 기록에 없는 항목만 질문한다.

- 계획 외 다른 화장품을 바꿨는가
- 계획과 다른 빈도·순서로 사용했는가
- 불편함보다 먼저 제품을 중단·재사용했는가
- 평소와 크게 달랐던 일이 있었는가

## 3. 분류와 다음 행동

연결 이슈: [#24 유지 후보·우선 확인·보류와 다음 행동 안내](https://github.com/sksksksksksss/service/issues/24)

### 분류 알고리즘

```text
안전 우선 조건인가?
  예 -> 전체 선택적 사용 중단·전문가 확인 안내를 먼저 표시
  아니오 -> 제품별 변경 사실 분류

안정 루틴에 같은 방식으로 있었고 이후 변경 기록이 없는가?
  예 -> 유지 후보

현재 실험에서 새로 추가되거나 교체된 제품인가?
  예 -> 우선 확인

안정 루틴 이후 함께 바뀌었지만 시점 또는 사용 정보가 불완전한가?
  예 -> 잠시 보류

기준 루틴 또는 시간 정보가 없어 위 조건을 재현할 수 없는가?
  예 -> 판단 어려움
```

한 제품에는 한 시점에 하나의 분류만 부여한다. 안전 우선 조건은 제품 분류를 없애지 않지만 화면에서 제품별 유지 안내보다 먼저 나온다.

### 결과 표현

| 분류 | 보여줄 사실 | 다음 행동 |
| --- | --- | --- |
| 우선 확인 | 안정 루틴 이후 이번 실험으로 바뀐 제품과 시작 시점 | 사용을 멈추고 추가 변경 없이 상태 확인 |
| 잠시 보류 | 함께 바뀌었지만 시점·사용 정보가 불완전한 제품 | 안정 확인 뒤 하나씩 별도 재시험 |
| 유지 후보 | 안정 루틴에 있었고 같은 방식으로 계속 사용한 제품 | 심한 불편이 아니라면 기존 방식 유지 후보 |
| 판단 어려움 | 누락·동시 변경·생활 변화 때문에 분류할 수 없는 범위 | 새 변경 없이 관찰하거나 전문가 확인 |

### 근거 강도

- `충분`: 확정 안정 루틴, 하나의 실험 제품, 완전한 사용·불편 시점이 있다.
- `제한적`: 분류는 가능하지만 생활 변화 또는 일부 누락이 있다.
- `부족`: 안정 기준이 없거나 여러 변경의 순서를 확인할 수 없다.

근거 강도는 인과 확률이 아니다. 현재 기록으로 분류 과정을 재현할 수 있는 정도다.

### AI 설명 계약

AI 입력은 서버가 계산한 분류, 근거 사실, 반대 사실과 부족한 정보다. 응답은 다음 필드로 제한한다.

- `summary`
- `evidence[]`
- `counter_evidence[]`
- `missing_information[]`
- `next_actions[]`
- `safety_notice`

제품 ID와 분류값은 AI가 바꿀 수 없다. 응답 검증에 실패하면 고정 템플릿으로 같은 사실을 보여준다.

### 완료 조건

- **Given** 하나의 안정 루틴과 하나의 새 실험 제품, **When** 불편함을 기록하면, **Then** 새 제품은 우선 확인이고 바뀌지 않은 안정 제품은 유지 후보로 분류된다.
- **Given** 계획 밖 제품 두 개를 함께 변경, **When** 시점이 불명확하면, **Then** 해당 제품은 잠시 보류 또는 판단 어려움이며 근거 강도가 낮아진다.
- **Given** 심한 불편, **When** Rescue를 열면, **Then** 유지 후보 안내보다 사용 중단과 전문가 확인 안내가 먼저 보인다.

## 4. 최종 결과 저장

연결 이슈: [#25 실험 결과 저장과 안정 루틴 선택적 갱신](https://github.com/sksksksksksss/service/issues/25)

### 결과 선택

| 결과 | 의미 | 안정 루틴 처리 |
| --- | --- | --- |
| 문제없이 사용 | 계획 기간 동안 사용자가 문제없이 사용했다고 판단 | 반영 여부를 별도로 질문 |
| 불편함 | 사용 중 불편함이 있었음 | 기존 안정 루틴 유지 |
| 보류 | 현재 결론을 내리지 않고 나중에 재시험 | 기존 안정 루틴 유지, 재시험 후보 가능 |
| 판단 어려움 | 기록·다른 변화 때문에 결론 부족 | 기존 안정 루틴 유지 |

최종 결과에는 실제 시작·종료일, 완료·건너뜀 관찰, 중단 기간, 주요 변화와 사용자 메모를 요약한다. 서비스가 결과를 대신 선택하지 않는다.

### 안정 루틴 갱신

`문제없이 사용` 결과에서 사용자가 `이 제품을 현재 루틴에 반영할게요`를 선택하면 다음과 같이 처리한다.

- 추가 실험: 후보 제품을 계획한 시간대·순서에 넣은 새 안정 루틴 버전을 만든다.
- 교체 실험: 교체 대상을 제거하고 후보를 넣은 새 안정 루틴 버전을 만든다.
- 사용자가 실제 사용 순서를 바꿨다면 최종 확인 화면에서 새 순서를 확인한다.
- 이전 안정 루틴은 그대로 보존한다.

반영하지 않으면 제품 경험은 문제없이 사용으로 남지만 현재 안정 루틴은 바뀌지 않는다.

### 완료 조건

- **Given** 문제없이 완료한 실험, **When** 루틴 반영을 동의하면, **Then** 결과와 연결된 새 안정 루틴 버전이 생성된다.
- **Given** 불편함·보류·판단 어려움 결과, **When** 완료하면, **Then** 현재 안정 루틴은 바뀌지 않는다.

## 5. Beauty Archive

연결 이슈: [#47 완료한 실험을 Beauty Archive에서 확인](https://github.com/sksksksksksss/service/issues/47)

### 기본 조회

Archive는 별도 결과 복사본이 아니라 실험·관찰·결과 이력을 조회해 구성한다.

목록에서 보여줄 내용:

- 제품명과 실험 목적
- 실제 사용 기간
- 결과 분류
- 필수 관찰 완료율
- 안정 루틴 반영 여부
- 재시험 연결 여부

상세에서 보여줄 내용:

- 당시 안정 루틴 버전
- 추가·교체 비교 결과
- 계획과 실제 사용 이력
- 관찰 타임라인
- Rescue 결과
- 최종 결과와 이후 안정 루틴

필터는 결과와 제품 종류를 지원하고 기본 정렬은 최근 완료순이다. 기록이 없으면 첫 제품 후보 찾기로 연결한다.

## 6. 다음 추천에 재사용

연결 이슈: [#26 과거 실험 결과를 다음 추천과 계획에 반영](https://github.com/sksksksksksss/service/issues/26)

개인 경험은 다음 순서로 반영한다.

1. 동일 제품의 가장 최근 완료 결과
2. 동일 제품의 이전 결과와 재시험 관계
3. 문제없이 사용한 현재 안정 루틴 조합
4. 두 번 이상 반복된 개인 관찰 패턴
5. 관련은 있지만 반대 사례가 있는 패턴

동일 제품의 결과가 서로 다르면 최신 결과만 정답처럼 쓰지 않는다. 사용 기간, 당시 루틴과 다른 변화가 달랐음을 함께 보여준다.

추천·계획 화면에서 개인 근거를 누르면 원래 Archive 실험으로 이동할 수 있어야 한다.

## 7. 개인 관찰 패턴

연결 이슈: [#27 누적 기록에서 개인의 성공·실패 패턴 확인](https://github.com/sksksksksksss/service/issues/27)

패턴 후보는 같은 정규화 제품, 성분, 기능 또는 제품군이 두 개 이상의 완료 실험에서 같은 방향의 결과와 함께 나타날 때만 만든다.

표시는 반드시 다음을 포함한다.

- 같은 방향 결과 횟수와 전체 관련 실험 수
- 반대 결과가 있다면 그 수와 링크
- 당시 함께 사용한 루틴 차이
- `관련 기록에서 반복됨`이라는 표현
- `원인으로 확인된 것은 아님`이라는 경계

예: `나이아신아마이드가 포함된 관련 실험 3개 중 2개에서 불편함을 기록했어요. 다른 1개는 문제없이 사용했습니다.`

한 번의 결과, 미완료 실험과 AI가 추측한 미확정 성분은 패턴 집계에 넣지 않는다.

## 8. 재시험과 이력 시각화

연결 이슈:

- [#28 보류 제품 재시험 계획과 일정 관리](https://github.com/sksksksksksss/service/issues/28)
- [#29 제품 사용 이력과 안정 루틴 변화 시각화](https://github.com/sksksksksksss/service/issues/29)

### 재시험

- 이전 결과가 보류 또는 판단 어려움인 실험에서 재시험을 만들 수 있다.
- 사용자는 먼저 현재 상태가 안정되었다고 확인한다.
- 새 실험은 이전 실험을 `parent_experiment_id`로 참조하고 당시 부족했던 관찰 항목을 계획에 포함한다.
- 진행 중인 다른 실험이 있으면 재시험을 시작할 수 없다.
- 이전 결과를 덮어쓰지 않는다.

### 타임라인

시간순으로 다음 사건을 같은 축에 표시한다.

- 안정 루틴 버전 확정
- 실험 시작·보류·재개·완료·취소
- 피부 불편과 Rescue
- 제품의 루틴 추가·교체·제외
- 재시험 연결

각 사건은 원래 상세 기록으로 이동한다. 타임라인은 인과관계 그래프가 아니라 사용 이력이다.

## 분석 이벤트

| 이벤트 | 발생 시점 | 속성 |
| --- | --- | --- |
| `rescue_started` | 불편 기록 후 Rescue 진입 | 안전 우선 여부, 동시 변경 여부 |
| `rescue_result_viewed` | 분류 확인 | 분류별 제품 수, 근거 강도 |
| `experiment_completed` | 최종 결과 저장 | 결과, 필수 완료율, 실제 기간 |
| `stable_routine_promoted` | 새 안정 루틴 동의 | 추가·교체, 새 버전 번호 |
| `archive_viewed` | 목록·상세 확인 | 기록 수, 필터 종류 |
| `personal_evidence_opened` | 추천에서 과거 기록 이동 | 동일 제품·패턴 구분 |
| `retrial_planned` | 재시험 계획 생성 | 이전 결과, 경과 일수 |
