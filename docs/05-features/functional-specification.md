# 통합 기능명세서

기능은 **P0 → P1 → P2 순서**로 구현한다. 상세 파일 하나에 여러 우선순위가 있으면 파일 상단의 `우선순위 범위`에서 P0 계약을 먼저 확인한다.

## P0 · 핵심 학습 순환

P0의 완료 기준은 기능 수가 아니라 아래 한 바퀴가 실제 데이터로 이어지는 것이다.

```text
최소 제품 의견 → 내 화장품 → 현재 루틴 → 7일 결과
→ 안정 루틴 또는 Rescue → 사용자가 다음 루틴 적용
→ 다음 제품 의견에서 과거 경험 재사용
```

| 순서 | 기능 ID | P0 결과 | 상세 |
| --- | --- | --- | --- |
| 1 | F-01 | 공개 MVP 계정과 사용자 데이터 경계를 만든다. | [보기](./functional-specs/F-01-account-personalization.md) |
| 2 | F-02 | 큐레이션 검색·직접 입력으로 제품을 내 화장품에 넣는다. | [보기](./functional-specs/F-02-catalog-products.md) |
| 3 | F-03 | 외부에서 본 한 제품을 현재·안정 루틴과 과거 결과로 설명한다. | [보기](./functional-specs/F-03-opinion-recommendation.md) |
| 4 | F-04 | 제품·아침/저녁·순서·빈도를 불변 루틴 버전으로 저장한다. | [보기](./functional-specs/F-04-routine.md) |
| 5 | F-05 | DAY 7의 사용 일치와 결과를 저장하고 안정 루틴을 만든다. | [보기](./functional-specs/F-05-seven-day-result.md) |
| 6 | F-06 | 불편 대화에서 변경 순위와 보수적인 다음 루틴을 제안한다. | [보기](./functional-specs/F-06-rescue.md) |
| 7 | F-07 | 현재 루틴과 마지막 안정 루틴의 차이를 보여준다. | [보기](./functional-specs/F-07-history-notifications.md) |
| 8 | F-08 | AI 실패·권한·출력 schema·상태 적용을 안전하게 통제한다. | [보기](./functional-specs/F-08-ai-jobs.md) |

## 상세 명세의 필수 구조

각 상세 파일은 다음 순서로 작성한다.

1. 사용자가 얻는 결과
2. 우선순위 범위: P0를 첫 행에 둔다
3. P0 정상 흐름·분기·실패·수용 시나리오
4. P1 계약
5. P2 계약
6. API와 데이터 변화

내부 클래스·함수·패키지는 명세하지 않는다. 사용자가 관찰하는 동작, 클라이언트-서버 계약과 데이터 의미를 명세한다.

## P0 공통 완료 기준

- 다른 사용자의 리소스는 같은 ID를 알아도 조회·변경할 수 없고 DB 복합 FK도 교차 소유 연결을 거절한다.
- 빈 상태, 정보 부족, AI 실패, 네트워크 재시도와 중복 제출을 처리한다.
- 사용자가 저장한 사실과 AI 해석을 화면과 응답에서 구분한다.
- AI가 실패해도 제품·루틴·결과와 사용자 메시지는 사라지지 않는다.
- AI plan은 생성 당시 기준 루틴이 여전히 ACTIVE일 때만 적용한다.
- 변경된 요구사항 ID, OpenAPI operation, 테이블과 테스트가 같은 PR에서 추적된다.
- P1·P2 미구현 기능은 P0 화면의 필수 경로가 아니며 실패 대체 경로로 요구하지 않는다.
