# 계정과 공통 서비스 기반

## 한눈에 보기

이 문서는 특정 화면 하나가 아니라 모든 사용자 흐름이 의존하는 인증, API, AI, 데이터 보호, 분석, 접근성, 테스트와 배포 규칙을 정의한다. 기술 구현은 [기술 스택](../03-technology-stack.md), 제품 계약은 [요구사항](../04-requirements.md)을 함께 따른다.

연결 요구사항: `FR-AUTH-001~003`, `NFR-*`

## 1. 계정과 기록 삭제

연결 이슈:

- [#45 이메일로 로그인하고 내 기록 불러오기](https://github.com/sksksksksksss/service/issues/45)
- [#46 계정과 SkinCause 기록 삭제](https://github.com/sksksksksksss/service/issues/46)

### 로그인

- 인증은 Supabase Auth 이메일 OTP 또는 매직 링크를 사용한다.
- Spring Boot는 JWT 서명, 발급자, 대상, 만료를 검증한다.
- 애플리케이션 사용자는 인증 subject와 1:1로 연결한다.
- 모든 개인 데이터 조회는 서버가 현재 사용자 식별자를 조건에 포함한다.

### 계정 삭제 흐름

1. 사용자가 설정에서 삭제되는 범위를 확인한다.
2. 다시 인증하거나 확인 문구를 입력한다.
3. 서버가 새로운 쓰기 작업을 막고 삭제 작업을 시작한다.
4. 전성분·구매 이미지와 알림 구독을 먼저 삭제한다.
5. 사용자 소유 루틴·후보·실험·관찰·AI 작업·LAB 기록을 삭제한다.
6. 인증 계정을 삭제하고 현재 세션을 종료한다.
7. 분석 도구에는 개인 연결을 제거한 집계 이벤트만 남긴다.

공용 카탈로그 제품은 삭제하지 않는다. 사용자가 만든 개인 제품은 다른 사용자가 참조할 수 없으므로 함께 삭제한다. 삭제 실패 단계가 있으면 운영 로그에 비민감 식별자로 재시도 작업을 남긴다.

백업 사본은 즉시 개별 삭제할 수 없으므로 공급자 보존 주기 안에서 최대 30일 후 제거된다는 내용을 사용자에게 알린다.

### 완료 조건

- **Given** 로그인한 사용자, **When** 삭제를 확정하면, **Then** 즉시 세션이 종료되고 본인 기록과 파일에 다시 접근할 수 없다.
- **Given** 다른 사용자의 삭제 요청 대상 ID, **When** 조작된 요청을 보내면, **Then** 현재 인증 주체의 데이터 외에는 삭제되지 않는다.

## 2. API 계약과 오류

연결 이슈: [#34 공통 API·오류 처리·데이터 규칙](https://github.com/sksksksksss/service/issues/34)

### 계약

- Spring Boot가 OpenAPI를 생성하고 생성된 TypeScript 클라이언트를 프론트가 사용한다.
- 날짜·시각은 API에서 UTC ISO 8601로 전달하고 화면에서 사용자 시간대로 표시한다.
- 열거형은 문서화된 값만 허용하고 알 수 없는 값은 무시하지 않고 계약 오류로 처리한다.
- 목록은 안정적인 정렬 기준과 커서를 사용한다.
- 생성 요청은 중복 클릭에 대비한 idempotency key를 받을 수 있다. 실험 완료·안정 루틴 승격·보상 생성에는 필수다.

### 오류 형식

```json
{
  "code": "ACTIVE_EXPERIMENT_EXISTS",
  "message": "진행 중인 실험을 먼저 완료하거나 취소해 주세요.",
  "fieldErrors": [],
  "traceId": "비민감 추적 식별자"
}
```

- `code`는 화면 분기와 테스트에 사용하는 안정적인 값이다.
- `message`는 사용자가 할 수 있는 다음 행동을 포함한다.
- 내부 예외, SQL, 프롬프트와 공급자 응답 원문을 노출하지 않는다.
- 같은 오류 규칙을 모든 도메인에 사용한다.

## 3. AI 작업 계약

AI 호출은 서버의 단일 `AiGateway`를 통한다.

| 작업 | 입력 | 구조화 출력 | 실패 대안 |
| --- | --- | --- | --- |
| INGREDIENT_EXTRACTION | 비공개 이미지 | 원문 행, 정규화 성분 후보, 신뢰 표시 | 직접 입력 |
| PURCHASE_ITEM_EXTRACTION | 비공개 이미지 | 제품명·브랜드 후보와 원문 위치 | 직접 검색 |
| GOAL_CLASSIFICATION | 사용자 목적 문장 | 기능 분류 후보 | 사용자가 직접 선택 |
| OBSERVATION_STRUCTURING | 선택 입력과 메모 | 확인 질문 후보 | 구조화 선택값만 저장 |
| EXPLANATION | 서버 계산 근거 | 요약·지지·반대·부족 정보 | 고정 템플릿 |

### 공통 규칙

- 출력은 작업별 JSON Schema로 검증한다.
- 제품 ID, 추천 순위, Rescue 분류와 권한 결과를 AI가 결정하지 않는다.
- 사용자에게 표시하는 구조화 결과는 수정 또는 확인할 수 있다.
- 작업 종류, 모델, 프롬프트·스키마 버전, 지연시간, 성공 여부를 기록한다.
- 숨겨진 추론 과정과 공급자 원문 전체를 영구 저장하지 않는다.
- 30초를 넘으면 요청을 종료하고 재시도 또는 직접 입력을 제공한다.

### 평가 세트

배포 전 고정 사례로 다음을 검사한다.

- 정상·흐린·일부 잘린 전성분 이미지의 스키마 준수
- 없는 성분이나 제품을 생성하지 않는지
- 추천 설명에 근거·반대 근거·정보 부족이 보존되는지
- Rescue 설명이 서버 분류를 바꾸지 않는지
- 진단·치료·원인 확정 금지 표현을 위반하지 않는지

실제 API를 사용하는 평가는 일반 단위 테스트와 분리하고 결과를 버전별로 비교한다.

## 4. 제품·성분 데이터 규칙

연결 이슈: [#33 제품·성분·기능 데이터 기반](https://github.com/sksksksksksss/service/issues/33)

- 공용 카탈로그 제품은 브랜드·제품명·제품 종류·바코드와 데이터 확인 상태를 가진다.
- 제품 성분은 표시 순서, 원문 이름, 정규화 성분과 출처를 가진다.
- 기능은 통제된 분류 체계를 사용하고 근거 출처와 운영 확인 여부를 가진다.
- 제품 정보 변경 시 기존 실험이 참조한 스냅샷은 바뀌지 않는다.
- 사용자 초안은 소유자를 가지며 운영 확인 전 공용 추천에 사용하지 않는다.
- 중복 병합은 운영자가 확인하며 바코드나 유사 이름만으로 자동 병합하지 않는다.

MVP 데이터셋은 핵심 시나리오와 중복·교체·정보 부족 사례를 모두 검증할 수 있는 고정 fixture를 포함한다. 제품 수 자체는 성공 기준이 아니다.

## 5. 개인정보와 로그

### 저장 금지

- API 키와 서비스 역할 키
- 사용자가 삭제한 이미지의 사본
- AI의 숨겨진 추론
- 분석 도구의 피부 관찰 메모·이미지·이메일
- 구매 이미지의 금액·주소·주문번호

### 애플리케이션 로그

허용: trace ID, 내부 사용자 UUID의 비가역 해시, 작업 종류, 상태 코드, 지연시간

금지: 이메일, 제품·피부 자유 문장, 이미지 URL, JWT, AI 입력·출력 원문

Sentry before-send 단계에서 민감 필드와 요청 본문을 제거한다. 운영자가 원문 데이터가 필요한 사용자 지원은 별도 동의 없이 제공하지 않는다.

## 6. 분석 이벤트

연결 이슈: [#35 핵심 사용자 행동 이벤트 수집](https://github.com/sksksksksksss/service/issues/35)

### 공통 속성

- 가명 사용자 식별자
- 이벤트 시각
- 앱 버전
- 실험 단계와 P0/P1 구분
- 세션 식별자

### 핵심 퍼널

```text
stable_routine_confirmed
  -> recommendation_viewed
  -> candidate_saved
  -> experiment_started
  -> quest_completed
  -> experiment_completed
  -> next_experiment_started
```

다음 지표를 이벤트에서 계산할 수 있어야 한다.

- 안정 루틴·후보 입력 완료율
- 추천 후 실험 시작률
- 필수 관찰 수행률
- 실험 완료·최종 결과 기록률
- 여러 제품 동시 변경률
- Rescue 이후 안정 루틴 보존률
- 다음 실험 재시작률

이벤트 이름과 속성은 코드 상수로 관리하고 문서와 자동 검사를 맞춘다.

## 7. 접근성·빈 상태·오류 복구

연결 이슈: [#48 핵심 흐름의 접근성·빈 상태·오류 복구](https://github.com/sksksksksksss/service/issues/48)

- 모든 입력은 연결된 레이블과 오류 설명을 가진다.
- 모달, 탭, 제품 순서 조작은 키보드로 사용할 수 있다. 드래그의 버튼 대안을 제공한다.
- 색만으로 결과·진행도·불편 정도를 구분하지 않는다.
- 애니메이션 감소 설정을 존중한다.
- 모바일 360px에서 가로 스크롤 없이 핵심 행동을 완료한다.
- 빈 상태는 데이터가 없는 이유와 다음 행동을 함께 보여준다.
- 네트워크 실패 시 이미 작성한 입력을 지우지 않는다.
- AI 실패 시 직접 입력 또는 규칙 기반 설명으로 전환한다.

### 자동 검사

- 백엔드 단위·PostgreSQL 통합 테스트
- 프론트 타입·컴포넌트 테스트
- OpenAPI 변경과 생성 클라이언트 동기화 검사
- 회원가입부터 두 번째 실험 추천까지 Playwright 핵심 경로
- 사용자 A가 사용자 B 데이터에 접근하지 못하는 권한 테스트
- 금지된 안전 표현과 AI 스키마 평가
- Flyway 마이그레이션을 빈 DB와 이전 배포 스키마 양쪽에서 실행

### 배포

- 모든 PR과 `main`에서 `make check`를 실행한다.
- `main` 배포는 웹·API·마이그레이션 버전을 같은 릴리스로 추적한다.
- 마이그레이션은 이전 애플리케이션과 호환되는 확장 후 축소 방식으로 작성한다.
- 배포 후 로그인, 안정 루틴 조회, 실험 조회와 헬스 체크를 자동 확인한다.
- 실패하면 이전 애플리케이션 버전으로 되돌리되 이미 적용된 데이터 마이그레이션을 파괴적으로 되돌리지 않는다.

### 운영 알림

- API 오류율과 지연시간 급증
- AI 작업 실패율과 타임아웃 증가
- 이미지 삭제 작업 실패
- 알림 예약 작업 정체
- 마이그레이션·배포 실패

## 완료 조건

- **Given** 사용자 A와 B, **When** 서로의 식별자를 바꿔 요청하면, **Then** 모든 개인 도메인에서 접근이 거부된다.
- **Given** AI 응답 실패, **When** 사용자가 핵심 흐름을 계속하면, **Then** 입력을 잃지 않고 직접 입력 또는 고정 설명으로 완료할 수 있다.
- **Given** 계정 삭제 요청, **When** 처리가 끝나면, **Then** 애플리케이션 데이터·파일·알림 구독과 인증 계정에 접근할 수 없다.
- **Given** `main` 릴리스, **When** 배포 파이프라인이 끝나면, **Then** 실제 URL의 핵심 스모크 테스트가 성공하거나 자동으로 실패 상태가 된다.
