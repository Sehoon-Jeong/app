# 관찰 퀘스트와 LAB 경험

## 한눈에 보기

사용자는 매일 일기를 쓰지 않는다. 첫 사용, 24시간 후, 중간, 종료와 평소와 다른 변화가 생긴 순간에만 짧은 관찰을 남긴다. LAB의 진행도와 성장은 이 유효한 기록과 실험 완료에만 연결된다.

연결 요구사항: `FR-OBS-001~006`, `FR-LAB-001~004`

## 1. 퀘스트 종류와 생성

연결 이슈: [#17 첫 사용·24시간·중간·종료 관찰 퀘스트](https://github.com/sksksksksksss/service/issues/17)

| 종류 | 생성 조건 | 필수 | 완료 결과 |
| --- | --- | --- | --- |
| FIRST_USE | 계획 확정 | 예 | 실제 시작 시각과 첫 관찰 저장 |
| EARLY_CHECK | 첫 사용 완료 | 예 | 첫 사용 24시간 후 상태 저장 |
| MID_CHECK | 첫 사용 완료 | 예 | 실험 중간 상태 저장 |
| FINAL_CHECK | 첫 사용 완료 | 예 | 최종 결과 입력으로 연결 |
| CHANGE_REPORTED | 사용자가 예정 밖 변화를 기록 | 아니오 | 변화 관찰 저장, 불편 시 Rescue 시작 |
| STOP_REPORTED | 사용자가 제품 사용 중단 | 아니오 | 중단 시점과 이유 저장 |
| RESTART_REPORTED | 사용자가 일반 사유 보류 후 재개 | 아니오 | 재개 시점 저장, 남은 일정 이동 |

`FIRST_USE`를 제외한 필수 퀘스트의 예정 시각은 실제 첫 사용 시각을 기준으로 확정한다. 계획만 만들고 시작하지 않은 시간은 관찰 기간으로 계산하지 않는다.

### 예정 시점 계산

- `EARLY_CHECK`: 첫 사용 시각 + 24시간
- `MID_CHECK`: 실제 시작일과 계획 종료일 사이 날짜의 중간. 소수 날짜는 뒤 날짜로 올림한다.
- `FINAL_CHECK`: 계획 종료일의 사용자가 선택한 기본 알림 시각
- 같은 날짜에 두 필수 퀘스트가 생겨도 별도 목적을 가진 경우 합치지 않는다. 화면에서는 한 묶음으로 보여줄 수 있다.
- 일시 보류 후 같은 실험을 재개하면 미완료 퀘스트를 보류 기간만큼 뒤로 이동한다. 완료한 관찰은 바꾸지 않는다.

## 2. 관찰 입력

### 모든 관찰의 필수 입력

- 현재 느낌: `변화 없음`, `편안함/개선`, `불편함`, `잘 모르겠음`
- 실제 관찰 시각: 기본은 현재 시각, 미래 입력 불가

### 선택 입력

- 짧은 메모
- 제품을 계획대로 사용했는지
- 사용하지 않았다면 이유

### 불편함을 선택했을 때만 묻는 항목

- 불편 유형: 건조·당김, 붉어짐, 가려움, 따가움·화끈거림, 오돌토돌함, 기타
- 정도: 가벼움, 중간, 심함
- 부위: 선택형과 기타
- 처음 알아차린 시점
- 평소와 크게 달랐던 일: 야외 활동, 평소와 다른 세안, 수면 부족, 다른 화장품 변경, 기타, 없음, 잘 모르겠음
- 전문가 도움이 필요하다고 느끼는지

불편 유형은 사용자가 경험을 기록하기 위한 용어이며 질환 분류로 사용하지 않는다. 메모와 `기타` 원문은 AI 설명에 필요할 때만 사용하며 분석 이벤트에는 보내지 않는다.

### 검증 규칙

- 미래 관찰 시각은 저장하지 않는다.
- 같은 퀘스트는 한 번만 완료한다. 수정은 같은 관찰의 수정 시각을 남긴다.
- 불편함을 선택하고 정도를 고르지 않았으면 완료할 수 없다.
- 제품을 사용하지 않은 날은 피부 결과를 억지로 선택하지 않고 `사용하지 않음`으로 저장할 수 있다.
- 심함 또는 도움 필요를 선택하면 저장 직후 안전 안내와 Rescue를 먼저 보여준다.

## 3. 오늘의 퀘스트와 리마인드

연결 이슈:

- [#18 앱 안에서 관찰 시점 확인](https://github.com/sksksksksksss/service/issues/18)
- [#52 브라우저 알림으로 관찰 시점 안내](https://github.com/sksksksksksss/service/issues/52)

### 인앱 상태

| 상태 | 조건 | 표시 |
| --- | --- | --- |
| 예정 | 예정 시각 전 | 날짜와 관찰 목적 |
| 오늘 | 사용자의 현지 날짜가 예정일과 같음 | 오늘 할 일 상단 |
| 놓침 | 예정일이 지났고 미완료 | 비난 표현 없이 지금 기록 또는 건너뛰기 |
| 완료 | 관찰 저장 완료 | 완료 시각과 수정 행동 |
| 중지 | 실험 PAUSED·CANCELLED | 알림 제외, 중지 이유 표시 |

놓친 퀘스트를 현재 시점에 기록하면 실제 관찰 시각과 뒤늦게 입력한 시각을 구분한다. 기억하지 못하면 건너뛰고 이유를 선택할 수 있다. 건너뛴 퀘스트는 완료율의 완료로 세지 않으며 데이터 부족으로 표시한다.

### 브라우저 알림

- 사용자가 기능 설명을 본 뒤 명시적으로 허용한 경우에만 요청한다.
- 알림 본문에는 피부 상태나 제품명을 넣지 않고 `관찰 퀘스트를 확인할 시간이에요`처럼 최소 정보만 표시한다.
- 권한 거부·브라우저 미지원·전송 실패가 인앱 퀘스트를 막지 않는다.
- 같은 퀘스트는 예정 알림 한 번과 놓침 알림 한 번을 넘지 않는다.

## 4. 진행도

연결 이슈: [#19 실험 진행도와 퀘스트 완료 보상](https://github.com/sksksksksksss/service/issues/19)

진행도는 `완료한 필수 퀘스트 수 / 생성된 필수 퀘스트 수`로 계산한다.

- 예정 밖 변화 기록은 유효한 연구 기록이지만 필수 진행도의 분모·분자에 넣지 않는다.
- 건너뛴 퀘스트는 완료로 세지 않는다.
- 결과를 수정해도 같은 퀘스트의 보상을 다시 만들지 않는다.
- 실험 취소 시 진행도는 이력으로 남지만 완료 연구로 보상하지 않는다.
- `FINAL_CHECK`에서 최종 결과까지 확정해야 100%가 된다.

화면에는 백분율만 보여주지 않고 `필수 관찰 2/4 완료`처럼 실제 의미를 함께 표시한다.

## 5. 완료 보상과 연구실 성장

연결 이슈:

- [#20 실험 완료 기록을 연구실에 추가](https://github.com/sksksksksksss/service/issues/20)
- [#21 조건 달성으로 배지와 연구실 장식 해금](https://github.com/sksksksksksss/service/issues/21)
- [#51 캐릭터와 연구실 테마 선택](https://github.com/sksksksksksss/service/issues/51)

### P0 기본 경험

- 필수 관찰을 완료하면 해당 퀘스트 카드가 연구 기록 도장으로 바뀐다.
- 최종 결과가 있는 완료 실험 하나는 연구실 선반에 하나의 연구 샘플 또는 기록 카드로 추가된다.
- 연구 기록은 원래 실험과 연결되며 한 실험당 하나만 존재한다.
- 실험 결과가 불편함이나 판단 어려움이어도 완료 기록을 남긴 행동은 동일하게 인정한다.

연구실 성장은 성공한 제품의 수가 아니라 **완료해 다음 판단에 쓸 수 있는 실험 수**를 보여준다. 실패 결과에 불이익을 주지 않는다.

### P1 확장 경험

배지와 장식은 조건이 명시된 경우에만 해금한다.

| 보상 | 조건 | 반복 획득 |
| --- | --- | --- |
| 첫 연구 완료 배지 | 첫 실험 결과 기록 | 아니오 |
| 꼼꼼한 관찰 배지 | 한 실험의 필수 관찰 100% | 실험별 기록은 남기되 배지는 한 번 |
| 루틴 보호 배지 | Rescue 후 안정 루틴을 기준으로 결과 완료 | 아니오 |
| 연구 샘플 | 완료한 실험 하나 | 예, 실험당 하나 |

연속 접속, 알림 클릭, 화면 체류에는 보상을 주지 않는다. 장식의 종류와 외형은 디자인 범위이며 조건은 이 표와 데이터 규칙을 따른다.

## 6. 예외 처리

- 퀘스트 저장 중 네트워크 오류가 나면 입력을 브라우저 메모리에 유지하고 재시도한다.
- 같은 퀘스트가 두 기기에서 동시에 완료되면 서버의 유일성 제약으로 하나만 만들고 최신 수정 내용을 사용자에게 확인시킨다.
- 시간대가 바뀌면 이미 확정된 절대 관찰 시각은 유지하고 현지 표시만 바꾼다. 아직 시작하지 않은 계획은 새 시간대로 다시 계산할 수 있다.
- 실험 종료일이 지났다고 자동 완료하지 않는다. 사용자가 최종 결과를 입력할 때까지 `결과 필요` 상태로 둔다.

## 완료 조건

- **Given** 14일 기본 실험을 시작한 사용자, **When** 첫 사용을 기록하면, **Then** 24시간·중간·종료 퀘스트가 실제 시작 시각 기준으로 예정된다.
- **Given** 불편함 관찰, **When** 저장하면, **Then** 불편 세부 항목이 저장되고 Rescue가 시작된다.
- **Given** 알림 권한 거부, **When** 관찰 예정일이 되면, **Then** 인앱 오늘의 퀘스트는 정상 표시된다.
- **Given** 필수 결과까지 완료한 실험, **When** 완료 처리되면, **Then** 연구실에 정확히 하나의 완료 연구 기록이 생긴다.
