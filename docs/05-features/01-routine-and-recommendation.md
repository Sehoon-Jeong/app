# 루틴 등록과 제품 추천

## 한눈에 보기

사용자는 로그인한 뒤 현재 문제없이 사용하는 루틴을 기준점으로 확정한다. 사용 목적과 변경 의도를 입력하면 서비스는 카탈로그 안에서 최대 3개의 실제 제품을 다음 실험 후보로 제안한다. 추천 제품과 직접 찾은 제품은 같은 후보 목록에서 관리한다.

연결 요구사항: `FR-AUTH-001~003`, `FR-RTN-001~004`, `FR-PRD-001~006`, `FR-REC-001~007`

## 1. 로그인과 첫 진입

연결 이슈: [#45 이메일로 로그인하고 내 기록 불러오기](https://github.com/sksksksksksss/service/issues/45)

### 시작 조건

- 사용자는 인증되지 않은 상태다.
- 개인 루틴·실험 URL에 직접 접근하면 로그인 화면으로 이동한다.

### 기본 흐름

1. 사용자가 이메일 주소를 입력한다.
2. Supabase Auth가 OTP 또는 매직 링크를 보낸다.
3. 인증이 완료되면 서버가 사용자 프로필을 찾거나 최초 프로필을 만든다.
4. 현재 안정 루틴이 없으면 Lab Setup으로, 있으면 현재 실험 대시보드로 이동한다.

### 규칙

- 이메일 존재 여부를 인증 전 화면에서 구분해 보여주지 않는다.
- 프론트가 전달한 사용자 ID를 소유권 근거로 사용하지 않는다. 서버는 JWT의 subject만 사용한다.
- 인증이 만료된 상태에서 작성 중이던 입력은 브라우저 임시 상태에 보존하고 재인증 후 복원한다. 민감한 사진 원본은 브라우저 영구 저장소에 넣지 않는다.

### 완료 조건

- **Given** 유효한 이메일 인증을 마친 사용자, **When** 다시 서비스에 접속하면, **Then** 자신의 안정 루틴 또는 Lab Setup으로 이동한다.
- **Given** 사용자 A의 토큰, **When** 사용자 B의 리소스 식별자로 요청하면, **Then** 서버는 리소스 존재 여부를 노출하지 않고 거부한다.

## 2. 안정 루틴 만들기

연결 이슈: [#7 현재 문제없이 쓰는 아침·저녁 루틴 저장](https://github.com/sksksksksksss/service/issues/7)

### 입력

- 루틴 이름: 선택, 기본값 `현재 루틴`
- 시간대: 아침 또는 저녁
- 제품: 카탈로그 제품 또는 사용자가 확인한 개인 제품
- 사용 순서: 시간대 안에서 1부터 연속된 정수
- 현재 상태 확인: `이 루틴을 현재 문제없이 사용하고 있어요`
- 피부 고민: 복수 선택 또는 `잘 모르겠어요`

아침과 저녁을 모두 입력할 필요는 없지만 전체 루틴에는 제품이 하나 이상 있어야 한다.

### 기본 흐름

1. 사용자가 아침·저녁 탭에서 제품을 검색해 추가한다.
2. 드래그 또는 순서 조작으로 사용 순서를 정한다.
3. 제품을 찾지 못하면 P1 직접 등록 흐름으로 이동한다.
4. 사용자가 현재 문제없이 사용 중임을 직접 확인한다.
5. 서버가 루틴과 제품 목록을 하나의 불변 `routine_version`으로 저장한다.
6. 이 버전이 사용자의 현재 안정 루틴이 된다.

### 규칙

- 같은 제품은 아침과 저녁에 각각 한 번 둘 수 있다.
- 같은 시간대에 같은 제품을 두 번 등록할 수 없다.
- 확정 후 기존 버전의 제품·순서를 직접 수정하지 않는다. 편집은 새 초안을 만들고 다시 확인한 뒤 새 버전을 생성한다.
- 안정 루틴 확정은 AI 결과가 아니라 사용자의 확인 이벤트다.
- 실험이 `PLANNED`, `ACTIVE`, `PAUSED`일 때 현재 안정 루틴을 임의 편집할 수 없다. 먼저 실험을 완료·취소해야 한다.

### 화면 상태

| 상태 | 표시와 행동 |
| --- | --- |
| 제품 없음 | 검색 또는 직접 등록 행동을 보여준다. |
| 검색 결과 없음 | 검색어 수정과 직접 등록을 제공한다. |
| 확인 미선택 | 저장은 초안으로만 가능하며 안정 루틴 확정 버튼은 비활성화한다. |
| 확정 완료 | 확정 시각과 아침·저녁 제품 수를 보여준다. |

### 완료 조건

- **Given** 제품이 하나 이상인 루틴, **When** 사용자가 안정 상태를 확인하면, **Then** 순서와 확정 시점이 있는 새 안정 루틴 버전이 생성된다.
- **Given** 이미 사용된 안정 루틴 버전, **When** 사용자가 현재 루틴을 편집하면, **Then** 원본은 유지되고 새 버전이 생성된다.

## 3. 제품 검색과 직접 등록

연결 이슈:

- [#10 제품 직접 입력과 전성분 사진 등록](https://github.com/sksksksksksss/service/issues/10)
- [#49 바코드로 카탈로그 제품 찾기](https://github.com/sksksksksksss/service/issues/49)
- [#50 구매 내역 이미지에서 제품 후보 등록](https://github.com/sksksksksksss/service/issues/50)

### 카탈로그 검색

- 제품명과 브랜드명 부분 일치를 지원한다.
- 검색 결과에는 브랜드, 제품명, 제품 종류와 데이터 확인 상태를 보여준다.
- 추천에는 운영 확인 상태의 카탈로그 제품만 사용한다.
- 사용자가 직접 찾고 선택하는 경우 개인 초안 제품도 실험 후보가 될 수 있지만 정보 부족을 표시한다.

### 직접 입력

사용자가 브랜드, 제품명과 제품 종류를 입력하면 개인 제품 초안이 생성된다. 공용 제품과 자동 병합하지 않는다. 운영자가 확인하기 전 다른 사용자의 검색 결과에 노출하지 않는다.

### 전성분 사진

1. 사용자가 전성분이 읽히는 이미지를 올린다.
2. 서버가 비공개 저장 위치와 처리 작업을 만든다.
3. AI가 원문과 정규화 후보를 구조화한다.
4. 사용자가 각 성분을 확인·수정하고 결과를 확정한다.
5. 확정된 성분만 비교에 사용한다.
6. 확인 후 원본 이미지를 삭제한다. 미완료 이미지는 업로드 7일 뒤 자동 삭제한다.

AI가 읽지 못한 항목은 비워 두고 사용자에게 표시한다. 비슷해 보이는 성분을 임의로 확정하지 않는다.

### 바코드

- 스캔한 값이 카탈로그의 고유 바코드와 정확히 일치할 때만 해당 제품을 보여준다.
- 일치하지 않으면 값만 개인 초안에 보존하고 직접 입력 또는 사진 등록으로 전환한다.
- 바코드 값의 유사성으로 제품을 추측하지 않는다.

### 구매 내역 이미지

- 외부 쇼핑몰 계정이나 결제 정보에 연결하지 않는다.
- 영수증·주문 내역 이미지에서 브랜드·제품명 후보와 행 위치를 추출한다.
- 사용자가 선택하고 확인한 항목만 개인 제품 초안으로 만든다.
- 금액, 주문번호, 주소 같은 정보는 제품 등록에 사용하지 않고 저장하지 않는다.

### 완료 조건

- **Given** 카탈로그에 없는 제품, **When** 사용자가 필수 정보를 입력하면, **Then** 본인만 볼 수 있는 제품 초안을 생성한다.
- **Given** AI가 일부 성분만 읽은 사진, **When** 사용자가 결과를 확인하기 전이면, **Then** 해당 성분은 확정 비교와 추천 근거에 사용되지 않는다.
- **Given** 카탈로그와 일치하지 않는 바코드, **When** 스캔하면, **Then** 다른 제품을 추측하지 않고 직접 등록으로 이동한다.

## 4. 추천 조건 입력

연결 이슈: [#8 피부 고민·사용 목적 기반 제품 추천](https://github.com/sksksksksksss/service/issues/8)

### 필수 입력

- 현재 안정 루틴
- 이번 사용 목적: 기능 분류 하나를 우선 목적으로 선택
- 변경 의도: `새 제품 추가` 또는 `기존 제품 교체`
- 교체일 경우 대상 안정 루틴 제품

### 선택 입력

- 피부 고민
- 원하는 제품 종류
- 사용 시간대
- 피하고 싶은 사용감 또는 제품 종류
- 추가 설명

피부 고민과 성분을 모르면 `잘 모르겠어요`를 선택할 수 있다. 이 선택은 추천을 막지 않고 정보 부족으로 표시한다.

## 5. 추천 후보 생성

### 추천 파이프라인

추천 순서는 같은 입력에서 재현할 수 있는 일반 로직으로 만든다. AI는 순위를 임의로 바꾸거나 카탈로그 밖의 제품을 만들지 않는다.

1. **자격 확인:** 운영 확인 제품, 판매·사용 가능 상태, 변경 의도와 제품 종류 조건을 확인한다.
2. **목적 적합성:** 제품의 확인된 기능이 사용자의 우선 목적과 연결되는지 확인한다.
3. **개인 경험:** 동일 제품 결과, 반복 관찰 패턴과 안정적으로 쓴 조합을 확인한다. 불편 결과는 자동 금지가 아니라 명시적인 반대 근거가 된다.
4. **루틴 변화:** 추가 기능, 기존 기능 중복, 교체로 사라지는 기능과 관찰 변수를 계산한다.
5. **정보 품질:** 성분·기능 출처와 확인 상태가 충분한 후보를 우선한다.
6. **정렬:** 위 근거의 우선순위로 정렬하고 최대 3개를 반환한다. 동일한 경우 데이터 확인 수준과 제품명 순으로 안정적으로 정렬한다.

제품명 정렬은 품질 순위가 아니라 같은 조건에서 결과가 흔들리지 않게 하는 마지막 규칙이다.

### 후보 카드에 표시할 내용

- 실제 브랜드와 제품명
- 사용 목적과 연결되는 확인된 기능
- 안정 루틴에서 새로 생기는 변화와 주요 중복
- 과거 개인 경험이 반영된 경우 해당 실험 링크
- 관찰할 항목
- 정보 확인 상태
- 지지 근거, 반대 근거, 부족한 정보

추천 결과가 없으면 조건 중 무엇 때문에 후보가 없는지 보여주고 카탈로그 검색과 직접 등록으로 연결한다.

### AI의 역할

- 계산된 추천 근거를 사용자가 이해하는 문장으로 바꾼다.
- 자유 입력 목적을 기존 기능 분류 후보로 구조화하고 사용자 확인을 받는다.
- 부족한 정보 중 순위나 계획을 실제로 바꿀 질문만 만든다.

AI는 제품을 생성하거나, 확인되지 않은 제품 효능을 근거로 추가하거나, 사용자 피부에 잘 맞는다고 확정하지 않는다.

### 완료 조건

- **Given** 보습 목적과 각질·미백 기능이 이미 포함된 안정 루틴, **When** 추천을 요청하면, **Then** 각질·미백 중복은 근거에 표시되고 보습 목적 후보가 우선된다.
- **Given** 관련 개인 불편 이력이 있는 후보, **When** 추천 목록에 포함되면, **Then** 과거 결과와 반대 근거가 숨겨지지 않는다.
- **Given** 적격 후보가 없는 조건, **When** 추천을 요청하면, **Then** 임의 제품 대신 부족한 데이터와 직접 찾기 행동을 보여준다.

## 6. 실험 후보로 저장

연결 이슈: [#9 추천 제품 또는 관심 제품을 실험 후보로 저장](https://github.com/sksksksksksss/service/issues/9)

사용자는 추천 카드 또는 제품 검색 결과에서 후보를 저장한다. 후보에는 다음 스냅샷을 남긴다.

- 선택한 제품 버전
- 추천 또는 직접 탐색 유입 경로
- 목적과 변경 의도
- 교체 대상 제품
- 후보 생성 시점의 안정 루틴 버전
- 당시 추천 근거와 정책 버전

같은 안정 루틴·제품·변경 의도의 미완료 후보는 중복 저장하지 않는다. 안정 루틴이 바뀌면 이전 후보는 남기되 `다시 비교 필요` 상태가 된다.

### 완료 조건

- **Given** 추천 후보, **When** 저장하면, **Then** 후보 목록에서 유입 경로와 변경 의도를 확인할 수 있다.
- **Given** 안정 루틴이 변경된 이전 후보, **When** 후보를 열면, **Then** 과거 비교 결과를 그대로 사용하지 않고 재비교를 요청한다.

## 분석 이벤트

| 이벤트 | 발생 시점 | 민감정보 제외 속성 |
| --- | --- | --- |
| `auth_completed` | 최초 인증 완료 | 신규 여부 |
| `stable_routine_started` | Lab Setup 시작 | 없음 |
| `stable_routine_confirmed` | 안정 루틴 확정 | 아침·저녁 제품 수 |
| `product_search_completed` | 검색 결과 확인 | 결과 수, 선택 여부 |
| `product_draft_confirmed` | 개인 제품 확정 | 입력 방식, 성분 수 |
| `recommendation_requested` | 추천 요청 | 목적 분류, 변경 의도, 과거 기록 사용 여부 |
| `recommendation_viewed` | 후보 근거 확인 | 후보 수, 정보 부족 여부 |
| `candidate_saved` | 실험 후보 저장 | 유입 경로, 추가·교체 |

검색어, 제품명 자유 입력, 피부 고민 원문과 이미지 내용은 분석 이벤트에 넣지 않는다.
