# F-05 DAY 7 결과 요구사항

[Feature 명세 #161](https://github.com/sksksksksss/service/issues/161)

## P0 · 결과와 안정 루틴

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| OBS-01 | 루틴 시작 현지 날짜를 DAY 1로 하고 DAY 7 00:00부터 앱 안에서 결과 행동을 노출한다. 미응답을 어떤 결과로도 추정하지 않는다. | 문제없었던 경험은 사용자가 돌아오지 않으면 수집되지 않는다. |
| OBS-02 | 결과를 남길 때 기록된 제품·순서·빈도와 실제 사용이 대체로 같았는지 먼저 묻는다. | 다른 조건의 결과를 해당 루틴 근거로 붙이지 않는다. |
| OBS-03 | 실제 사용 일치, 관찰 결과와 다음 행동을 분리해 저장한다. `불편 없음`, `불편함`, `아직 모르겠음`을 각각 완료, Rescue 시작, 결론 보류로 저장한다. P0는 결론 보류 뒤 새 일정을 자동 생성하지 않는다. | 관찰과 시스템 행동을 같은 enum에 섞지 않고 자동 연장은 P1로 남긴다. |
| OBS-04 | 실제 사용이 같고 불편 없음으로 완료한 현재 루틴만 마지막 안정 루틴으로 승격하고 과거 안정 이력을 보존한다. | 다음 비교와 Rescue의 기준점을 만든다. |
| OBS-05 | 불편함을 선택하면 이전 결과 대화를 지우지 않고 Rescue로 이어간다. | 같은 사실을 다시 입력시키지 않는다. |
| OBS-07 | 실제 사용이 기록과 다르면 안정 루틴으로 쓰지 않고 실제 사용대로 새 루틴을 저장하게 한다. | 잘못된 조건을 강한 개인 근거로 만들지 않는다. |

## P1 · 추가 관찰과 조기 결과

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| OBS-06 | 사용자가 `7일 더 보기`를 선택하면 같은 루틴에 새 schedule을 최대 두 번 만든다. | 결론을 강요하지 않되 무한 반복을 막는다. |
| OBS-08 | DAY 1~6에 루틴을 바꿀 때 지금까지 결과를 선택적으로 `EARLY_CHECK`로 남긴다. 숫자 신뢰도는 저장하지 않는다. | 짧은 경험을 보존하되 안정 근거와 구분한다. |
