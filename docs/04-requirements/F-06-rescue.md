# F-06 AI Rescue 요구사항

[Feature 명세 #162](https://github.com/sksksksksksss/service/issues/162)

## P0 · 변경 중심 Rescue

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| RSC-01 | 사용자는 DAY 7 전후와 관계없이 자유 문장으로 불편함을 말해 Rescue를 시작한다. | 불편이 생긴 순간이 핵심 진입점이다. |
| RSC-02 | Rescue는 이전 사용자·AI 메시지를 지우지 않고 아래로 이어지는 채팅이며 빠른 답만 선택 버튼을 함께 제공한다. | 사용자가 판단 과정을 따라가고 정정할 수 있어야 한다. |
| RSC-03 | AI는 발생 시점, 실제 사용, 함께 바뀐 것과 사용자가 말한 심한 정도 중 판단에 필요한 빈칸만 한 번에 하나씩 묻는다. 모르면 건너뛸 수 있다. | 장문의 진단 설문과 억지 추정을 막는다. |
| RSC-04 | 서버는 마지막 안정 루틴과 현재 루틴의 제품·순서·시간대·빈도 차이를 계산하고 사용자가 실제와 다른 변경을 고친다. | AI 기억이 아니라 저장된 변경을 출발점으로 삼는다. |
| RSC-05 | P0 확인 우선순위는 새로 추가·제거된 제품, 시간대·순서·빈도 변화, 함께 바뀐 항목, 발생 시점과 관련 과거 기록으로 계산한다. 큐레이션된 공식 사실은 있을 때만 보조 근거로 쓴다. | 먼저 변경점 정리 엔진의 가치를 검증하고 외부 연구 엔진과 섞지 않는다. |
| RSC-06 | 각 확인 순위는 먼저 보는 이유, 반대 개인 기록과 정보 부족을 함께 보여주며 원인·범인·확률로 표현하지 않는다. | 행동 순서를 진단처럼 오해하지 않게 한다. |
| RSC-07 | AI는 보유 제품 안에서 유지·제외·순서·빈도가 명확한 보수적 다음 루틴 하나를 제안한다. 새 제품을 추가해 해결하지 않는다. | 분석을 실제 다음 행동으로 연결한다. |
| RSC-08 | 사용자가 정확한 plan을 승인한 뒤에만 독립된 새 루틴 버전을 만들고 새 DAY 7을 시작한다. 적용 직전 plan의 기준 루틴과 현재 ACTIVE를 비교한다. | 오래된 AI 결과가 최신 루틴을 덮어쓰지 않게 한다. |
| RSC-12 | 현재 루틴이 없으면 일반 안전 안내와 자유 기록만 제공하고 제품별 확인 순위와 개인화 루틴을 만들지 않는다. | 비교 사실이 없을 때 거짓 정밀도를 만들지 않는다. |
| RSC-13 | 사용자가 심각하거나 빠르게 악화된다고 말하면 제품 순위와 루틴 제안을 중단하고 전문가 확인을 권한다. 질환·응급도·진료과는 정하지 않는다. | 서비스가 할 수 없는 의료 판단의 경계를 지킨다. |

## P1 · 반복 경험과 약한 기준점

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| RSC-09 | 사용자는 plan을 적용하지 않고 Rescue 기록만 남길 수 있으며 현재 루틴과 schedule은 바뀌지 않는다. | AI 제안을 따르지 않은 실제 행동도 보존한다. |
| RSC-10 | 새 루틴의 반복 Rescue는 과거 case를 덮지 않고 관련 개인 근거로 참조한다. | 반복 경험이 다음 확인 순위에 쓰이게 한다. |
| RSC-11 | 안정 루틴이 없으면 기준점이 약함을 밝히고, 과거 불편 없음 기록이 있는 보유품 안에서 최소 루틴을 제안할 수 있다. | 초기 사용자에게 거짓 확신 없이 제한된 도움을 준다. |
