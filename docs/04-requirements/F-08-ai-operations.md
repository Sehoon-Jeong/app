# F-08 AI·보안·운영 요구사항

[Feature 명세 #164](https://github.com/sksksksksksss/service/issues/164)

## P0 · AI와 데이터 경계

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| AI-01 | OpenAI API는 자연어 구조화, 필요한 추가 질문과 계산된 결과 설명을 맡는다. P0에서는 광범위한 제품 추천 검색을 맡기지 않는다. | 정적 enum으로 다 담기 어려운 사용 맥락을 다룬다. |
| AI-02 | 서버는 사용자 권한, 실제 제품·루틴 ID, 비교 사실, 확인 순위, 상태 전이와 AI 출력 schema를 검증한다. | AI가 시스템 사실과 최종 상태를 결정하지 못하게 한다. |
| AI-04 | AI가 실패해도 사용자가 저장한 제품·루틴·결과·대화는 남고 고정 안내, 직접 편집과 재시도 경로를 제공한다. | 외부 장애가 핵심 기록을 잃게 하지 않는다. |
| SEC-01 | 모든 개인 리소스에서 인증 사용자의 소유권을 검사하고 개인 자식 데이터의 복합 FK가 같은 사용자 부모만 참조하게 한다. | API 누락이나 내부 버그로도 교차 사용자 연결을 저장하지 않는다. |
| SEC-02 | 비밀값과 실제 사용자 데이터를 저장소, 로그, 프롬프트 예제와 테스트 fixture에 넣지 않는다. | 개발 과정의 유출을 막는다. |
| OPS-01 | SQLite 스키마는 Flyway migration으로만 변경하고 모든 연결에서 FK를 켠다. 핵심 상태는 CHECK·UNIQUE·복합 FK로 보강한다. | 단일 인스턴스 MVP에서도 모순된 개인 기록을 저장하지 않는다. |
| OPS-02 | AI와 Object Storage 호출은 DB 쓰기 트랜잭션 밖에서 실행한다. | 외부 지연으로 SQLite 쓰기 잠금을 오래 잡지 않는다. |
| OPS-03 | 한 번만 반영할 쓰기는 멱등 키를 사용하고 AI plan 적용 전 기준 루틴과 ACTIVE 루틴을 비교한다. | 더블 탭·재시도·오래된 제안으로 중복 상태를 만들지 않는다. |

## P1 · 근거와 비동기 운영

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| AI-03 | 외부 제품 사실을 사용한 AI 주장은 evidence snapshot을, 개인 주장은 정확한 개인 기록을 참조하고 지지·반대·불확실성을 구분한다. | 출처 링크만 붙인 그럴듯한 설명을 막는다. |
| AI-05 | 긴 AI 작업은 논리적 request, 모델 run과 worker job을 분리한다. 재시도별 모델·prompt·원본 출력·검증 오류를 보존하고 만료 lease를 재회수한다. | 실패·재시도와 고아 작업을 재현하고 복구한다. |
