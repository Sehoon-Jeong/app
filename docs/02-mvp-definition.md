# SkinCause MVP 정의

## 한눈에 보기

SkinCause의 MVP는 3주 안에 실제 URL로 배포되는 제품이다. 화면을 많이 만드는 것이 아니라 아래 한 바퀴가 실제 데이터로 연결되어야 한다.

> 안정 루틴 등록 → 새 제품 후보 비교·추천 → 실험 계획 → 관찰 퀘스트 → Rescue → 결과 저장 → 다음 실험에 재사용

- **개발 목표:** P0와 P1을 연결해 사용할 수 있는 상태
- **반드시 증명할 것:** 사용자가 한 제품의 실험을 끝내고 그 결과를 다음 선택에 쓸 수 있는가
- **아닌 것:** 발표용 클릭 프로토타입, 전체 화장품 데이터베이스, 피부 진단 서비스
- **범위 기준:** GitHub Project의 `Priority` 필드가 최종 기준이며 P0·P1은 MVP, Pn은 이후다.

## 이번 MVP에서 답할 질문

> 사용자는 현재 루틴과 새 제품을 등록하고, 제안된 순서에 따라 제품을 시험하며, 필요한 관찰과 최종 결과를 다음 실험에 쓸 수 있는 경험 데이터로 남기는가?

실제 치료 효과나 특정 제품의 의학적 원인을 맞히는지는 검증 대상이 아니다.

## 우선순위의 의미

### P0 — 핵심 흐름을 성립시키는 기능

P0 하나라도 빠지면 사용자가 실험 한 바퀴를 완주할 수 없다.

- 계정 생성과 자신의 데이터 구분
- 계정과 개인 기록 삭제
- 아침·저녁 안정 루틴과 제품 순서 등록
- 피부 고민, 사용 목적과 새 제품 후보 등록
- 현재 루틴과 후보의 기능·주요 성분 차이 분석
- 루틴에 맞는 후보 제품과 시험 순서 제안
- 사용 순서, 확인 시점과 관찰 항목이 포함된 실험 계획
- 첫 사용·중간 확인·변화 발생·종료 시점의 관찰 퀘스트
- 불편함 발생 시 최근 변경점 확인과 다음 행동 안내
- 실험 결과 저장과 Beauty Archive 조회
- 저장한 경험을 다음 후보 비교와 계획에 반영
- 진행도와 실험 완료 보상이 보이는 기본 LAB 경험
- 앱 안에서 오늘·놓친 관찰 시점 확인

### P1 — 3주 MVP의 사용성과 신뢰를 완성하는 기능

P1은 시간이 남으면 하는 장식이 아니다. P0 흐름을 실제 사용자가 덜 헤매고 더 믿을 수 있게 만드는 MVP 범위다. 다만 일정이 위험해지면 PM이 P1 안에서 구현 깊이를 줄일 수 있다.

- 제품을 찾지 못했을 때 직접 등록하고 다시 쓰는 흐름
- 전성분 사진을 구조화하고 사용자가 결과를 확인·수정하는 흐름
- 바코드 정확 일치 검색과 구매 내역 이미지의 제품 후보 추출
- 추천과 분류에 근거, 반대 근거와 부족한 정보 표시
- 과거 성공·불편 경험의 공통 요소와 유사 실험 비교
- 피부가 안정된 뒤 재시험 일정과 상태 변화 표시
- 사용자가 허용한 경우의 브라우저 관찰 알림
- 연구실의 정체성이 느껴지는 캐릭터·배지·아카이브 시각화
- 실패·로딩·빈 상태와 접근성 등 핵심 흐름의 완성도

P1의 세부 범위는 기능 명세에서 인수 조건과 함께 확정한다. 캐릭터 종류나 애니메이션 수처럼 콘텐츠 양이 커지는 부분은 먼저 줄인다.

### Pn — 검증 후 만드는 기능

사용 기록이나 브랜드 수요가 충분해야 의미가 있는 기능이다. 이번 MVP에는 포함하지 않는다.

- 실제 사용자 집단을 이용한 코호트 분석
- 대규모 제품 탐색과 자동 구매 추천
- 브랜드 실험 개설, 참여자 관리와 분석 대시보드
- 전문가 상담과 개인 이력 전달
- 커머스, 광고와 결제
- 네이티브 모바일 앱과 모바일 앱 푸시 알림

## 사용자가 실제로 할 수 있어야 하는 일

MVP가 끝나면 사용자는 다음 시나리오를 중단 없이 수행할 수 있어야 한다.

1. 회원가입 후 현재 문제없이 사용하는 아침·저녁 루틴을 저장한다.
2. “보습을 강화하고 싶다”처럼 목적을 입력하고 여러 제품 후보를 비교한다.
3. 현재 루틴과 겹치는 기능과 새로 생기는 변수를 확인한다.
4. 먼저 시험할 후보와 이유를 보고 실험을 시작한다.
5. 제안받은 시점에 짧은 관찰 퀘스트를 완료한다.
6. 불편함을 기록하면 마지막 안정 루틴 이후의 변경점과 다음 행동을 확인한다.
7. 실험 결과를 확정하고 Beauty Archive에서 다시 본다.
8. 두 번째 제품을 등록했을 때 첫 번째 실험의 결과가 비교와 안내에 반영된다.

## MVP 완료 기준

아래 조건을 모두 만족해야 “MVP를 만들었다”고 말한다.

- 누구나 접근 가능한 실제 URL에 배포되어 있다.
- 새 계정으로 핵심 시나리오를 처음부터 끝까지 수행할 수 있다.
- 새로고침하거나 다시 로그인해도 루틴, 실험과 관찰 기록이 남아 있다.
- 미리 준비한 제품만으로도 핵심 시나리오가 작동하고, 없는 제품은 정해진 방식으로 추가할 수 있다.
- 불편함이 있는 경로와 문제없이 완료하는 경로가 모두 작동한다.
- 첫 실험 결과가 두 번째 실험의 안내에 실제로 사용된다.
- LAB 진행 상태와 완료 보상이 행동 결과에 맞게 바뀐다.
- 진단이나 확정적 원인 판정으로 오해할 표현이 없다.
- 핵심 지표를 확인할 이벤트가 수집된다.
- 합의한 자동 테스트와 배포 전 점검을 통과한다.

발표 당일에 시간을 빠르게 넘기는 데모 모드는 사용할 수 있다. 다만 데모 모드가 실제 시간 기반 실험과 데이터 저장을 대신해서는 안 된다.

## 검증 지표

초기에는 숫자의 높고 낮음보다 사용자가 어디에서 멈추는지 찾는 데 집중한다.

| 지표 | 확인하려는 것 |
| --- | --- |
| 안정 루틴·후보 입력 완료율 | 시작에 필요한 입력 부담이 감당 가능한가 |
| 후보 추천 후 실험 시작률 | 비교 결과가 다음 행동으로 이어지는가 |
| 필수 관찰 수행률 | 퀘스트가 필요한 기록을 남기게 하는가 |
| 실험 완료율·최종 결과 기록률 | 한 바퀴를 끝낼 수 있는가 |
| 두 개 이상 제품 동시 변경률 | 서비스가 변수 수를 실제로 줄이는가 |
| 다음 실험 재시작률 | 기록이 다음 탐색의 가치로 이어지는가 |
| Rescue 이후 안정 루틴 보존률 | 잘 쓰던 제품까지 포기하는 손실을 줄이는가 |

LAB 게임화의 효과는 방문 횟수가 아니라 관찰 수행률과 실험 완료율로 판단한다.

## 이번에 의도적으로 하지 않는 것

- 모든 국내외 화장품을 지원하는 완전한 제품 데이터베이스
- 피부 사진을 이용한 상태 판정과 질환 진단
- 특정 제품이나 성분을 트러블 원인으로 확정하는 기능
- 개인 기록이 없는데도 정밀 개인화처럼 보이는 코호트 결과
- 완성형 레벨·꾸미기·재화 시스템
- 브랜드용 제품 테스트 운영 도구
- 전문가 상담, 처방, 치료 효과 판단

이 기능들이 중요하지 않아서가 아니라, 핵심 흐름과 사용자 행동이 검증된 뒤 만들어야 근거가 생기기 때문이다.

## 범위를 바꾸는 규칙

- P0를 빼거나 Pn을 MVP로 올리는 결정은 PM이 한다.
- 일정이 부족하면 먼저 P1의 콘텐츠 양과 표현 깊이를 줄인다.
- 새 기능을 넣을 때는 “핵심 시나리오의 어느 단계를 개선하는가”에 답해야 한다.
- 답하지 못하는 기능은 이번 MVP에 넣지 않는다.
- 최종 범위는 [GitHub Project](https://github.com/orgs/sksksksksksss/projects/1)의 `Priority`와 `Milestone`으로 관리한다.
