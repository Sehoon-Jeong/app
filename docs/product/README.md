# 제품 기획 기준

이 폴더는 SkinCause를 처음 보는 사람이 제품의 전체 흐름과 변하지 않아야 할 규칙을 빠르게 이해하기 위한 기준 문서다.

구현할 기능의 상세 조건은 GitHub Story가 원본이다. 이 폴더는 Story를 화면 순서로 연결하고, 여러 Story가 함께 지켜야 하는 규칙을 설명한다.

## 읽는 순서

1. [User Story Map](./story-map.md)에서 이번 MVP의 범위와 전체 흐름을 본다.
2. [사용자 흐름](./user-flows.md)에서 정상 완료, 불편 발생, 다음 추천까지 실제 사용 과정을 본다.
3. [제품 규칙](./product-rules.md)에서 용어, 상태 전이, Rescue와 AI의 책임 경계를 확인한다.
4. 구현할 때는 Story Map에 연결된 GitHub Story의 본문과 완료 조건을 따른다.

## 문서별 역할

| 문서 | 답하는 질문 |
| --- | --- |
| [User Story Map](./story-map.md) | 사용자가 어떤 순서로 제품을 쓰며, P0·P1·Pn은 어디까지인가? |
| [사용자 흐름](./user-flows.md) | 각 단계에서 사용자가 무엇을 결정하고 서비스가 무엇을 돌려주는가? |
| [제품 규칙](./product-rules.md) | 어떤 상황에서도 지켜야 할 규칙과 AI·일반 코드·사용자의 책임은 무엇인가? |

## 다른 문서와의 관계

- 제품의 문제와 타깃은 [기획 정리](../01-product-brief.md)가 설명한다.
- 3주 안에 검증할 범위는 [MVP 정의](../02-mvp-definition.md)가 설명한다.
- 요구사항 ID와 검증 기준은 [요구사항 명세](../04-requirements.md)가 관리한다.
- Story가 공유하는 상세 정책은 [기능 기준](../05-features/README.md)이 관리한다.
- 저장 구조와 제약은 [데이터 모델](../06-data-model/README.md)이 관리한다.

같은 내용을 여러 곳에 복사하지 않는다. 제품 결정이 바뀌면 먼저 이 폴더의 흐름과 규칙을 확인하고, 영향을 받는 Story·요구사항·데이터 모델을 함께 고친다.
