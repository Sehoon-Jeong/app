# AI 프롬프트와 대화 계약

SKN의 AI는 자유로운 화장품 상식 엔진이 아니다. 서버가 선별한 제품 사실·현재 루틴·과거 경험을 사용자가 이해하기 쉽게 연결하는 기록 파트너다.

## 하나의 채팅, 네 가지 맥락

| 모드 | 진입점 | AI가 답할 수 있는 근거 | 답하지 않는 것 |
| --- | --- | --- | --- |
| `GENERAL` | 하단 AI 탭 | 개인 기록, 현재 루틴, 패턴 후보 | 기록에 없는 피부 상태 추론 |
| `PRODUCT` | 제품 상세의 AI 버튼 | 확인된 제품 사실, 내 루틴, 유사한 과거 기록 | 피부 적합·안전·구매 성공 보장 |
| `RECOMMEND` | 탐색의 다음 제품 찾기 | 서버가 고른 실제 후보 3개, 내 루틴, 과거 기록과 패턴 | 카탈로그 밖 제품 생성·적합 확률·구매 보장 |
| `PATTERN` | 패턴 상세의 AI 버튼 | 패턴을 지지·반대하는 원본 기록 | 피부 타입·영구 성향 판정 |
| `RESCUE` | 불편 기록 후 이어서 보기 | 비교 기준 이후 변경, 발생 시점, 과거 경험, 서버 제안 | 진단·응급도 판정·원인 특정 |

모드는 프롬프트와 서버 맥락만 바꾸며, 화면과 메시지 API는 공통으로 쓴다.

## 프롬프트 조립

```text
shared-v1.txt       전 모드의 사실·안전·표현 경계
+ {mode}-v1.txt     GENERAL / PRODUCT / RECOMMEND / PATTERN / RESCUE 전용 규칙
+ 서버 맥락       제품·루틴·경험·패턴의 실제 ID와 사실
+ 사용자 메시지   지금 보낸 문장
```

프롬프트 원문은 [`backend/src/main/resources/prompts`](../../backend/src/main/resources/prompts)에 있다. 대화 이력은 최근 8개 메시지만 제공해 비용과 상관없는 맥락 혼입을 줄인다.

## 추천 입력 규칙

채팅 첫 화면과 대화 중의 추천 입력은 서로 다르게 처리한다.

### 첫 화면

- 프론트엔드가 고정한 예시 3개를 보여준다.
- 개인 기록이 없어도 의미가 통하는 문장만 쓴다.
- 위치: `frontend/src/pages/ChatPages.tsx` 안의 `INITIAL_PROMPTS`.

### 대화 시작 후

- 매 AI 답변이 `suggestedReplies` 1~3개를 같이 반환한다.
- 방금 답한 내용을 반복하지 않고, 사용자가 다음에 궁금할 법한 짧은 1인칭 문장으로 만든다.
- 없는 제품·기록·화면을 있는 것처럼 제안하지 않는다.
- 프론트엔드는 이 배열을 그대로 보여줄 뿐 추가 문장을 만들지 않는다.
- AI 연결 실패 시에도 서버 모드별 fallback이 최대 3개를 반환한다.

```json
{
  "answer": "현재 기록에서는 가벼운 마무리에 만족한 경험이 반복됐어요.",
  "suggestedReplies": [
    "아침과 저녁 기록을 나눠서 볼래",
    "반대로 아쉬웠던 기록도 보여줘"
  ],
  "evidenceRefs": ["E-1", "E-2", "E-3"]
}
```

OpenAI Responses API의 Structured Outputs로 위 JSON Schema를 강제한다. 서버는 응답을 다시 검증하고, 추천 입력은 중복 제거 후 3개·80자 이하만 저장한다. `evidenceRefs`는 서버가 실제로 전달한 ID만 허용하며 모델이 만든 가짜 참조는 버린다.

`answer`는 모바일 채팅에 맞은 Markdown으로 받는다. 첫 문단은 결론, 이후 내용은 최대 4개의 `###` 소제목·목록·강조로 구조화한다. 모바일에서 읽기 어려운 표와 H1, HTML, 링크, 코드 블록은 생성하지 않는다. 프론트엔드는 raw HTML을 허용하지 않는 Markdown 렌더러를 사용하며, 기존 평문 답변의 줄바꿈도 그대로 보여준다.

사용자가 별도로 AI 대화를 시작하지 않은 메모 원문은 공급자에게 보내지 않는다. AI 맥락에는 감정 선택, 사용자가 고른 태그, 불편 여부처럼 구조화된 기록만 들어간다.

## Rescue의 역할 분리

```text
사용자 불편 기록
→ 서버의 안전 확인
→ AI가 필요한 추가 정보를 한 번에 하나씩 질문
→ 서버가 비교 기준 이후 변경과 확인 순서를 계산
→ AI가 지지·반대·정보 부족을 설명
→ 사용자가 버튼으로 승인
→ 서버가 새 루틴과 독립된 7일 사용 경험 생성
```

심하거나 빠르게 악화된다는 사용자 표현이 확인되면 서버가 제품 순위와 루틴 제안을 차단한다. AI는 이 결정을 뒤집지 않는다.

## 모델·비용·실패 정책

- 기본 모델: `gpt-5.6-terra`
- reasoning effort: `low`
- 최대 출력: 650 tokens
- 재시도: 429·5xx·timeout에만 1회
- 저장: OpenAI `store: false`
- 실패: 사용자 메시지를 먼저 DB에 저장한 뒤 fallback 답변을 남긴다.

Terra는 최저가 모델보다 한국어 맥락·상충 근거·보수적 표현이 중요한 SKN 대화에서 균형을 취한 선택이다. 최신 가격과 모델은 [OpenAI API 가격](https://developers.openai.com/api/docs/pricing)에서 확인한다.

## 비밀값

`OPENAI_API_KEY`는 루트 `.env`에만 두고 Spring 서버가 읽는다. 프론트엔드 번들·Git·로그에는 포함하지 않는다.
