# SKN 애셋 삽입·등록

애셋 원본은 저장소의 `assets/`에 있고, 각 파일이 무엇인지·어떤 상황에 쓰는지는 `references/asset-catalog.md`에 정리돼 있다. 실물을 보지 못한 사람도 이 카탈로그만 읽으면 올바른 파일을 고를 수 있다. **원본 폴더명과 파일명은 절대 바꾸지 않는다.** 한글 이름 그대로 참조한다.

## 1. 애셋 위치와 카탈로그

- 원본 위치: 저장소 루트의 `assets/로고`, `assets/아이콘`, `assets/루틴 원본 이미지`
- 카탈로그: `references/asset-catalog.md` — 파일별 생김새, 포맷, 투명 여부, 크기, 쓰는 상황을 설명한다.
- `assets/썸네일.png`는 발표·README 전용이며 제품 UI 애셋이 아니다. 코드에 넣지 않는다.

작업 전 `references/asset-catalog.md`에서 요청에 맞는 파일을 먼저 찾는다. 계절·시간대 배경처럼 변형이 여러 개인 항목은 카탈로그의 매핑 표로 어떤 파일을 쓸지 정한다.

## 2. 기존 애셋을 코드에 넣기

1. 카탈로그에서 목적에 맞는 파일과 그 특성(투명 여부·정지/영상·용도)을 확인한다.
2. 프레임워크가 쓰는 위치로 원본을 **파일명 그대로** 복사하거나 참조한다. 이 저장소의 프론트는 Vite라, 빌드에 태우지 않고 바로 서빙할 파일은 `frontend/public/` 아래, 번들에 포함해 import할 파일은 `frontend/src/assets/` 아래에 둔다.
3. 정지 이미지(PNG)는 `<img>`나 CSS `background-image`로, 애니메이션(MP4/MOV)은 `<video autoplay muted loop playsinline>`으로 넣는다. 투명 배경 애셋은 어떤 배경 위에도 얹히도록 배경색을 강제하지 않는다.
4. 접근성을 위해 이미지에는 의미 있는 `alt`를, 장식용에는 빈 `alt=""`를 준다. 자동재생 영상은 항상 `muted`로 둔다.
5. 넣은 뒤 카탈로그의 설명과 실제 쓰임(계절·시간대·성공/로딩 등 상태)이 맞는지 확인한다.

한글 파일명이 도구·번들러에서 부담되면, **원본 `assets/`는 그대로 두고** 배포 위치의 복사본만 영문으로 바꾼다. 원본과 카탈로그의 이름은 유지한다.

## 3. 새 애셋 등록 (사용자가 파일을 새로 줬을 때)

사용자가 이미지·영상 파일을 새로 건네면 아래 순서로 처리한다.

1. 파일을 **직접 열어 내용을 확인한다.** 정지 이미지는 그대로 보고, 영상은 대표 프레임을 뽑아 본다.
   ```bash
   # 영상 대표 프레임 추출 (macOS 내장, ffmpeg 없이). 25초 넘으면 중단.
   ( qlmanage -t -s 600 -o <출력폴더> "<영상경로>" >/dev/null 2>&1 ) & P=$!; sleep 25; kill $P 2>/dev/null
   ```
2. 크기·포맷·투명 여부를 확인한다.
   ```bash
   sips -g pixelWidth -g pixelHeight -g hasAlpha "<이미지경로>"
   ```
3. 원본을 `assets/`의 알맞은 하위 폴더에 **받은 파일명 그대로** 복사한다. 새 범주면 폴더를 새로 만든다.
4. `references/asset-catalog.md`에 항목을 추가한다. 실물을 못 본 사람도 이해하도록 다음을 적는다.
   - 무엇이 보이는가(형태·색·질감을 구체적으로)
   - 포맷, 픽셀 크기, 투명 배경 여부, 정지/영상 여부
   - 어떤 UI 상황에 쓰는가, 대응하는 정지본/영상본이 있으면 함께 표기
5. 계절·시간대·상태처럼 변형 묶음이면 카탈로그의 매핑 표에 행을 추가한다.

## 규칙

- 원본 폴더명·파일명은 바꾸지 않는다. 설명은 카탈로그에서만 한다.
- 사진·영상 속 인물, 원본 이미지 자체는 새로 만들거나 변형하지 않는다. 있는 애셋을 배치할 뿐이다.
- `assets/썸네일.png`는 제품 UI에 넣지 않는다.
- 브랜드 표기는 `SKN`이며, N은 좌우 반전된 형태의 전용 글리프다. 텍스트로 대체하지 말고 로고 애셋을 쓴다.
